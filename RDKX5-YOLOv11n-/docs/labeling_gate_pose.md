# 门（gate）4 角点打标规范 · 组内作业单

> 用途：水下门的 pose 数据集标注。**照着这张单子做，标出来的标签才能直接进训练、进板端。**
> 判据：标注只做两件事 —— ① 框住门 ② 点出四个角；其余都是防止"教坏模型"的细节。
> 数据来源：`data/derived/AUV_5_upload_roboflow/`（每批一个文件夹 + 一份 manifest CSV）。

---

## 0. 一句话原则

**只标你真实看得见的东西。看不见的角点就用"不可见"开关关掉 —— 绝不要为了凑满 4 个点去猜位置。**

这条是整个规范里唯一不能让步的：猜出来的坐标会教模型"在错的地方给高置信角点"，
上一版模型"角点乱飞、崩到画面角落"的一部分就是这么来的。

## 2. 建 Roboflow 工程（**顺序错了整套数据作废**）

1. New Project → Project Type 选 **`Keypoint Detection`（Pose）**
2. 关键点数量 **4**，名字与顺序**必须是**：

   | 槽位 | 名字 | 含义 |
   |---|---|---|
   | 1 | `TL` | 门框左上角 |
   | 2 | `TR` | 门框右上角 |
   | 3 | `BR` | 门框右下角 |
   | 4 | `BL` | 门框左下角 |

   * schema 顺序 = 标签里 `x1 y1 v1 x2 y2 v2 …` 的下标顺序，与板端解码一一对应。
   * **不要加第 5 个槽位**：加了导出会多一列，模型输出通道从 12 变 15，板端直接对不上。

---

## 3. 框（Bounding Box）怎么画

* **一个门一个框**，框要**把管子本身的厚度一起框进去**，不是只框四个角点的紧包围盒。
  * 依据：现有 844 张的「框面积 ÷ 角点紧包围盒面积」中位数 = **1.635**（四边各外扩约 25px）。新标的框按同样习惯画，分布才一致。
* 框不要把旁边的门一起框进来（多门时各画各的）。

---

## 4. 四个角点怎么点

* 位置：**门框管子中心线的交点**（左上 / 右上 / 右下 / 左下），不是管子外缘。
* 顺序：**点的时候随意**，Roboflow 会让你把它指派到 TL/TR/BR/BL —— 只要**指派对**就行。
* 精度：远处小门请放大再点（差 2~3px 在 640 输入上就是半个格）。

---

## 5. 看不见的角点（最容易标错的地方）

**操作：选中那个角点，按 `Delete` 删掉它。**（不是点一个大概位置）

### 为什么必须删、不能猜

YOLO pose 每个门固定 4 个关键点槽位、格式上不能少标。看不见的角点**必须记成 `v=0`**：

| v | 含义 | 训练时 |
|---|---|---|
| 2（可见） | 正常标 | 参与坐标损失 |
| 0（不可见） | **用 Delete 删掉** | **坐标损失被屏蔽**，只训练"这个角点不可见" |

❌ 把出画的角点硬点到画面边缘、或猜一个大概位置 → 模型学会"在错的地方给高置信角点"，
就是上一版"角点乱飞、崩到画面角"的来源之一。

### 关于"删掉之后的坐标"（这条别搞错）

**唯一要守住的是 `v=0`；坐标是多少不重要。**

实测现有 844 张（同样是 Roboflow 标的）：**869 个 v=0 角点，坐标散布在画面各处、
中位数接近画面中心，没有任何一个正好是 `(0,0)`** —— 删除后写什么坐标是导出工具自己的行为，
ultralytics 只用 `v != 0` 判断要不要算坐标损失，所以那些坐标是无害的。

**不要**为了"让坐标看着对"去把删掉的角点点到画面角落 —— 那反而把它变成可见角点（v=2），
正好做错。

## 6. 一张图有多个门 / 没有门

* **有几个门就标几个**：每个门各自一个框 + 各自 4 个角点（Roboflow 支持一图多个 pose 实例）。
  * 只标主门的后果：没标的门会被模型当成"错检"，多框问题永远治不好。
* **画面里没有门** → **不打任何标注**（保持无标签）。回收后我们按背景图（负样本）处理。
  * 这类图很有价值（模型现在几乎没见过"没有门"的画面），但**不要**随便画个框。

---

## 7. Tags（每张图必打 2 个，决定难例会不会被加权）

**① 水质**（三选一）：`w_clear` 清水 / `w_mid` 中水 / `w_turbid` 浊水

**② 门框完整性**（三选一，按画面里**最主要的那个门**判）：

| tag | 规则 | 对应画面 |
|---|---|---|
| `g_full4` | 4 个角点都在画面内且看得见 | 正常整门 |
| `g_part` | 1~3 个角点在画面内 | 贴脸、出画、被挡 |
| `g_tube` | 没有任何角点可见 | 只剩一根横管/立柱 |

**③ 场景**（可选多选）：`s_multi`（画面有 ≥2 个门）/ `s_close`（门占画面 >30%，贴脸）/ `s_none`（没有门，此时不用打 ②）

> 完整性 tag 必打：它决定 `g_part`/`g_tube` 这类难例是否被上采样（×2 ~ ×2.5），也是我们做分层评测的依据。

## 8. 导出

1. Generate → Export → 格式选 **`YOLOv8 Pose`**（部分版本叫 `YOLO11 Pose` / `Pose`）。
2. 把 zip 路径给对接人，后续由脚本处理（**不要自己手动改导出的 data.yaml**）：
   ```bash
   # ① v=1 → v=0（写新目录）
   python scripts/1_prepare/pose/check_pose_export.py <导出目录> --out <新目录>
   # ② 归一化：截尾随全零槽位 + 校验 flip_idx 与角点顺序
   python scripts/1_prepare/pose/prepare_pose_dataset.py <导出目录>
   python scripts/2_train/build_stage_dataset.py --stage 1 --base data/datasets/AUV_5_gate-pose.yolov8 \
       --add <上面产物> --human-tags <tag CSV> --negatives output/preview/auv5_pose/judgment/negatives_log.csv
   ```
3. Roboflow 的 `kpt_shape` 常带多余槽位、`flip_idx` 写的是恒等 `[0,1,2,3,4]`，
   这两处由上面的脚本统一修正为 `[4,3]` / `[0,1,2,3]` —— **这两个值不能动**（与现版权重、板端一致）。

## 9. 错误做法对照表（照着自查）

| ❌ 错误 | 后果 | ✅ 正确 |
|---|---|---|
| keypoint 顺序不是 TL,TR,BR,BL | 标签语义全错，与板端解码对不上 | 建工程时按下表建，别改名 |
| 加了第 5 个关键点 | 导出多一列，输出通道 12→15 | 只建 4 个 |
| 出画角点被点到画面边缘/猜位置 | 模型学会在错的地方给高置信角点 | **选中它按 Delete 删掉** |
| 把删掉的角点又点到画面角落"补位" | 它变成可见角点(v=2)，坐标进了损失 | 删掉就行，坐标是什么不重要 |
| 只标主门 | 没标的门变成"错检" | 有几个门标几个 |
| 改了文件名 | 对不回原池子，水质/tag 全丢 | 别改名 |
| 忘了打 `g_*` tag | 难例不上采样、分层评测做不了 | 每张必打 ② |
| 框只框角点 | 与现有 844 张分布不一致 | 把管子厚度框进去 |
| 没有门却画了个框 | 教模型在空场景里找门 | 不打标注 |

## 11. 回收后我们做什么（标注同学不必管）

1. `prepare_pose_dataset.py`：截掉尾随全零关键点槽位、校验角点顺序与 `flip_idx`
2. `build_stage_dataset.py`：**累积**并入（每期都含之前所有数据，防遗忘）+ 按 tag 过采样 + 负样本空标签 + 排除评测保留集
3. `train_yolo11n.py` 训练 → `eval_benchmark.py` 用固定基准验收（图级坏率 / 板端口径 / 误检率 / 三域可用率）

# 上下位机通信协议：yaw / pitch / roll 相对角度控制

更新：2026-10-06。对应本目录下位机源代码。本次仅修改下位机；RDK 上位机尚未增加三轴选择接口，也未自动上传或烧录。

## 1. 串口与编号

- 控制串口：下位机 USART2，9600 baud，8 数据位、1 停止位、无校验、无硬件流控（8N1）。
- 下行：11 字节定长；上行：15 字节定长。所有 `byte[n]` 都从 0 开始，包含帧头。
- 普通运动帧通常每 50 ms 发送；自动角度任务建议每 100 ms 重发相同执行帧。
- 一个任务选择一个轴；三个轴不能作为三个独立任务同时执行。其他轴继续保持各自已有目标。

## 2. 上位机 → 下位机：11 字节

| 下标 | 第几个字节 | 含义 |
|---|---|---|
| byte[0] | 1 | 帧头 `0xA5` |
| byte[1] | 2 | 原手动 yaw 通道 |
| byte[2] | 3 | 原前进/后退通道 |
| byte[3] | 4 | 原升降通道 |
| byte[4] | 5 | 原左右平移通道 |
| byte[5] | 6 | 原辅助滚轮通道，现有上位机默认 165 |
| byte[6] | 7 | 原速度档 SC，0/1/2；现有上位机默认 1 |
| byte[7] | 8 | 指定角度轴：0=不发起任务，1=yaw，2=pitch，3=roll |
| byte[8] | 9 | bit7=执行标志；bit6～0=角度编码高 7 位 |
| byte[9] | 10 | 角度编码低 8 位 |
| byte[10] | 11 | 指令编号：1～255，0 用于同步 |

手动运动轴 `byte[1..4]` 的上位机中位值为 128。自动角度执行帧应将四个手动轴回中，避免人为动力叠加。

`byte[7]=0` 表示不发起新的指定角度任务，不关闭底层姿态 PID，不恢复首次姿态，也不取消已有任务。
普通帧不会改变正在执行任务的轴。执行位为 1 时，轴值不在 1～3 的请求会被忽略。
仅设置 `byte[7]` 而不设置执行位，不会开始旋转。

下行没有校验和，也没有额外帧尾。帧中任意字节都可能等于 A5，必须按固定长度处理；下位机接收半帧后若字节间隔超过 25 ms，会丢弃半帧并重新寻找帧头。

### 2.1 相对角度编码

角度单位为度，输入范围 `[-180,180]`，编码范围 `[0,32767]`：

```text
N = floor((angle + 180) * 32767 / 360 + 0.5)
byte[8] = 0x80 | ((N >> 8) & 0x7F)
byte[9] = N & 0xFF
```

下位机解码：

```text
N = ((byte[8] & 0x7F) << 8) | byte[9]
relative = N * 360 / 32767 - 180
```

分辨率约 0.01099°；0° 编码为 16384，解码约 +0.00549°，属于量化误差。

### 2.2 轴方向和目标

只在首次接受新任务时，以当时 IMU 测量值计算目标：

| byte[7] | 目标赋值 | 正负方向 |
|---|---|---|
| 1 | `Angle.Yaw_ori = wrap(Angle.Yaw - relative)` | 正值右转、负值左转，沿用原固件右转时 yaw 减小的约定 |
| 2 | `Angle.Pitch_ori = wrap(Angle.Pitch + relative)` | 正值使 IMU pitch 增大，负值减小 |
| 3 | `Angle.Roll_ori = wrap(Angle.Roll + relative)` | 正值使 IMU roll 增大，负值减小 |

`wrap` 将角度归一化到 `(-180,180]`。pitch/roll 的正值不直接等同于物理抬头或向某侧倾斜，需依安装方向实测。
±180° 两个方向对应同一个姿态目标，不能用该姿态协议保证恰好半圈时的运动方向。

协议的可编码范围不等于机械和姿态解算的可达范围：pitch 使用欧拉角，靠近 ±90° 时存在表示边界/奇异性；本版本没有增加姿态范围限制，不能据此认为任意 ±180° pitch 目标都可达到。

pitch/yaw 继续使用原有两路 plant PID，roll 使用当前已接入的 `wrap(Angle.Roll - Angle.Roll_ori)` 误差。新目标、取消和本地恢复会清除相关 PID 的历史误差/积分/输出，保留增益及限幅。pitch/yaw 共用两路 PID，因此清除的是共同控制器历史，另外两个轴的目标值不因接受新任务而改变。

### 2.3 同步、执行、重发

1. 每个新任务之前，发送同步帧：`byte[7..10] = 00 00 01 00`，运动轴回中。
2. 等待新的有效回传：`byte[2]=0` 且 `byte[13]=0`。同步会取消正在执行的任务。
3. 选一个 1～255 的编号，发送轴、角度和执行位。
4. 约每 100 ms 重发同一个编号、轴和角度，直到收到该编号的完成反馈，或上位机决定取消。
5. 下位机按所选轴完成后保持目标；重复执行帧不会再次旋转，完成值也不会被重复帧清除。

只有编号、轴和角度编码全部相同的重复执行帧才刷新 750 ms 接收时限。同编号但轴或角度不同的帧不修改目标，也不刷新时限。
任务运行中忽略其他编号的新执行请求；下位机未同步或 IMU 首次校准未完成时不接受新任务。
一个失败/取消编号不能直接通过重发重新启动；应重新同步并发起新任务。

### 2.4 取消

```text
byte[7] = 0
byte[8] = 0
byte[9] = 1
byte[10] = 要取消的编号，或 0
```

取消命令按编号识别，不依赖 byte[7]。编号 0 表示取消并同步；非 0 仅在匹配当前编号时生效。
执行中的任务取消后，将该轴的目标锁定为当前测量值，完成标志为 0。已完成任务取消/同步只清除完成状态，不改变已保持的目标。
750 ms 没收到匹配执行帧，也执行相同的取消处理。普通中性帧不会刷新此时限。
保留用户要求：没有“IMU 不更新自动取消”或“下位机旋转 20 秒自动取消”。上位机自身原有任务超时仍可主动发送取消。
取消不是推进器断电；底层姿态和定深控制仍按原逻辑工作。

## 3. 下位机 → 上位机：15 字节

每约 100 ms 尝试回传一帧（串口忙时顺延）。

| 下标 | 含义 |
|---|---|
| byte[0..1] | 帧头 `AA 55` |
| byte[2] | 当前接受的旋转编号，0=同步状态 |
| byte[3..4] | 当前深度，单位 cm |
| byte[5..6] | 目标深度，单位 cm |
| byte[7..8] | 当前 IMU roll，单位 0.01° |
| byte[9..10] | 当前 IMU pitch，单位 0.01° |
| byte[11..12] | 当前 IMU yaw，单位 0.01° |
| byte[13] | 所选轴任务完成：1=完成，0=未完成/取消/无任务 |
| byte[14] | `sum(byte[0..13]) & 0xFF` |

所有双字节数值均为有符号 int16、小端（低字节在前）。上行 byte[7] 是 roll 数据的一部分，与下行 byte[7] 的轴选择无关。
姿态遥测是 IMU 当前角度，不是减去首次姿态后的偏差。当前协议不回传三轴目标或首次姿态，也不回传轴标志；上位机根据自己发出的编号记录轴。

完成条件：所选轴的环绕误差绝对值 <3°，对应角速度绝对值 <5°/s，连续满足至少 200 ms。
当前 `Imu.c` 沿用原映射：Pitch_rate=gyro.wx、Roll_rate=gyro.wy、Yaw_rate=gyro.wz；pitch/roll 轴和角速度对应关系尚需实机核实，本次未改 IMU 坐标定义。
完成标志沿用变量名 `Yaw_Finish`，现在表示 yaw/pitch/roll 中本次所选轴的完成情况。
上位机应校验帧头、长度、校验和及编号，只有本次编号的完成 1 才能结束任务。

## 4. 示例（完整下行帧，十六进制）

下列示例使用辅助值 A5、01，四个手动运动轴均为 80（十进制 128）：

```text
普通中性帧：          A5 80 80 80 80 A5 01 00 00 00 00
同步/取消所有任务：   A5 80 80 80 80 A5 01 00 00 01 00
yaw 右转90°，编号1：  A5 80 80 80 80 A5 01 01 DF FF 01
yaw 左转90°，编号2：  A5 80 80 80 80 A5 01 01 A0 00 02
pitch 增加30°，编号3：A5 80 80 80 80 A5 01 02 CA AA 03
roll 减少30°，编号4： A5 80 80 80 80 A5 01 03 B5 55 04
取消编号4：           A5 80 80 80 80 A5 01 00 00 01 04
```

示例中的旋转是不同任务示范，不能在前一任务尚未结束时直接切换编号并期待并行执行。

## 5. 下位机首次姿态保存和调用

第一次收到校验通过且包含加速度、角速度和姿态的完整 IMU 帧时，保存当时 Pitch_ori / Yaw_ori / Roll_ori 的副本。
仅保存本次上电的第一次有效值，旋转、取消、同步及 `imu_reset_offset()` 都不覆盖；掉电后不保留。
这些值是上电首帧姿态，是否对应机身水平取决于上电时摆放。

下位机主循环可调用：

```c
#include "Imu.h"
#include "RC.h"

FLOAT_Angle initial;
if (imu_get_initial_attitude(&initial)) {
    /* initial.pit / initial.yaw / initial.rol：只读副本 */
}

/* 按需调用；不要每帧重复调用恢复接口。 */
RC_RestoreInitialAttitude(TURN_AXIS_YAW);   /* 恢复首次 yaw 目标 */
RC_RestoreInitialAttitude(TURN_AXIS_PITCH); /* 恢复首次 pitch 目标 */
RC_RestoreInitialAttitude(TURN_AXIS_ROLL);  /* 恢复首次 roll 目标 */
RC_RestoreInitialAttitude(TURN_AXIS_NONE);  /* 恢复全部三个目标 */
```

恢复接口返回 1 表示目标已设置，不表示实际姿态已经到达；返回 0 表示尚未具备有效姿态/校准或参数非法。
恢复前取消当前活动任务；若恢复的是另一个轴，被取消轴先锁到当前位置。未选中且无活动任务的其他轴目标保持不变。
恢复保留原指令编号、清除完成标志，防止迟到重复帧重新执行旧任务。随后开始上位机任务需重新同步。
本地接口不新增串口操作码；byte[7]=0 不表示恢复首次姿态。

## 6. 上位机适配清单

本次没有修改上位机运行代码。适配时需要：

1. `base/hw/uart.py`：旋转构帧/请求增加轴选择；yaw=1、pitch=2、roll=3。执行帧必须显式覆盖 byte[7]，不能仅依赖辅助通道默认值。
2. 普通/中性帧 byte[7] 设为 0；`cfg/comm.yaml` 中 `aux_axis` 的索引 6 对应整帧 byte[7]。
3. `common/motion/turn_deg.py`：增加 pitch/roll 正负相对角度入口；原过门 yaw 路径明确选 1。
4. 重发同一编号、轴和角度；同步/取消、15 字节回传校验及匹配编号完成的流程沿用。

当前本地上位机默认 byte[7]=1，旧 yaw 执行帧恰好仍对应 yaw；但还没有 pitch/roll 选择能力。若只把默认值改成 0，而不在 yaw 执行帧明确写 1，会导致原旋转不启动。

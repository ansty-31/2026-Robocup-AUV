## 2. 机制：七条

1. **纵向零点全局**：在算 `dyn` 的三处（`_on_pose` / `_on_width` / `_on_coarse`）**统一减** `dy_target`。
   它是**测量约定**，不是某条判据的私事 —— `through.center_y`、`loiter.dy_max`、`heave` 的 PID 目标
   都吃同一个 `dyn`，只在 align 里减会让它们全部错位。
2. **对中判据分档**：`gate/motion/channels.py::_aligned(dxn, dyn, node, kx, ky)`，
   位姿档 / width / coarse 各用各的带；给档位节点里缺那两个键时**回退**到 `comm.gate.align`。
3. **转向前置条件 = `align ∧ 机身稳`（并行）**：数 `align.confirm_frames` 帧。
   "机身稳"读**遥测**：`|Δroll|,|Δpitch|,|Δyaw| ≤ body_delta_max_deg`（无遥测 fail-open）。
   ⚠️ 为什么不是"align 5 帧 + 再稳 5 帧"：实测 `align ∧ 机身静` 的 **10 帧窗口恒为 0**，串行等于永不起转。
4. **ψ 先 EMA 10 帧再比 tol**，目标角也用平滑值；快 EMA(≈4 帧) 只留日志字段 `hdg_fast`。
5. **过门居中闸 = 本档对中带 × `through.loose`**（`channels._center_ok`），
   与 `through.center_x/center_y` 取 **AND** ⇒ 只会更严、不会放松旧闸。
6. **两段式冲刺**（`exits._tick_through`）：段① `fast_ms` 用 `surge.through` 快冲；
   段② 到 `confirm_ms` **降到 `surge.creep`** 保持。新增日志字段 `through_stage`（进入帧也写）。
   `fast_ms=0` = 整段满速（旧行为，一行回退）。
7. **`PID` 新增可选 `bias`（执行器死区补偿）**：出死区即把输出抬到执行器死区之上，再随 kp 线性升到
   `out_max`；`bias=0` = 旧行为。`pid_kw` 透传（可选键）。

顺带修一处既有小 bug：`exits._tick_lost` 在反向平移窗口里**自己把 action 预置成 `sway_back`**，
窗口恰在该帧关闭时撤不回来（会记/发一帧已结束状态的指令）⇒ 改为传中性动作，由 `_set_info` 的平移块决定。

几处关键的"为什么"：

- **`dy` 零点不在 0**：`dyn` 中位 −0.30，逐档 −0.20 / −0.28 / −0.34 ⇒ 门恒在光轴一侧（相机装高 + 常态抬头）。
  不搬掉它，任何纵向阈值都在偏置上打滑，`heave` 也会永久单向压（实测 `heave>0` 203 帧 / `<0` 13 帧）。
- **`cross` 为什么能提到 1.5**：full 档 `z<1.5` 那 9 帧的 `k` std 只有 3.3%（`z∈[1.5,2.0)` 是 3.7%），
  是全程最稳的一段；提到 1.5 后参与 `z≤cross` 计数的帧从 14 涨到 22、最长连续从 7 涨到 11，
  `cross_confirm_frames=4` 才第一次真正可满足。
- **远端为什么"压阈值"而不是压缩实测值**：`z` 的实测分布在 **1.958–3.123 之间是空带**
  ⇒ `dist_max_m` / `relock_away_m` 取该区间内任何值**行为完全相同**；
  真正有作用的只有把 `pnp.z_max`（唯一被读的远端键）压到 3.0。
- **`k` 在数据上是"档位指纹"**：coarse 238/244 落 `k<0.42`、width 96/97 落 `k≥0.42`、full 全落 `k≥0.42`；
  三档 `k` 中位差 3.7 倍 ⇒ 任何"按倍数的带宽"都覆盖不了两群，所以新下限取**绝对值方向**。

## 4. `sway` 一直顶在 ±0.55：病根与修法

| 项 | 数（有测量 236 帧） |
|---|---|
| PID 的真实误差 | 日志里的**原始 `dx`**（画面中心基准），不是折到主点后的值 |
| 误差尺度 | `\|dx\|` 中位 **0.090**、p25 0.047、p75 0.226、max 0.421 |
| 比例区宽度（旧） | `out_max/kp − deadzone` = 0.069 − 0.05 = **0.019**，占满幅 **1.9%** |
| 必然饱和 | `\|dx\| ≥ 0.0688` ⇒ **63% 的帧**（full 78% / coarse 78% / width 26%） |
| 分箱核对 | `\|dx\|∈(0.069,0.08]` 实测饱和 **100%**；`≤0.05` 恒 0 |
| 极限环 | 符号每 **7.6 帧（1.0 s）** 翻一次；按权限修完中位行程 0.099 m 也要 **1.0 s** |
| 执行器死区 | `\|DOF\| < 0.138` 推力为 0 ⇒ **只降增益会把"一直顶满"换成"一直没推力"** |
| 对照 | `heave`（kp=1.0）实测 **0% 饱和** ⇒ 同尺度下 sway 的 kp 大了 8 倍 |

同一批误差样本离线复算：`kp=8`（旧）饱和 64% / 比例区 10% / 输出中位 0.550
→ 新参数 **饱和 1% / 比例区 72% / 输出中位 0.240**。
**回放实跑**（同一趟日志）：下发 `sway` 饱和 **0%**、比例区 32%、非零输出 **0.185~0.518 且 100% ≥ 死区 0.138**。

> ⚠️ `comm.motion.pid_sway` 是 **ball 与 gate 共用**（"一处调、两个任务同时生效"是既定不变量，
> `tests` 里有专门用例钉它）⇒ 撞球的横向居中回路**一并改变**。回退 = `kp` 改回 8.0 并删掉 `bias`。

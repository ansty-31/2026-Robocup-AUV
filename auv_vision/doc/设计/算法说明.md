## 5. 任务算法要点

### 5.1 撞球（task1_2/ball.py）
运动链（视觉识别与运动逻辑都在本项目内，ball 权重为 bbox 检测）：

| 相位 | 下发 | 转移 |
|---|---|---|
| SEARCH | 脉冲旋转（spin/pause）+ 周期性慢速前进探测 | 见球 → CENTER |
| CENTER | **仅 yaw + heave**（surge=0、sway=0），水平+竖直居中 | 连续 `center_confirm_frames` 帧居中 → APPROACH |
| APPROACH | **分级前进 + 仅 sway**（yaw=0、heave=0） | 面积(EMA) ≥ `dash_ratio` 连续 `dash_confirm_frames` 帧 → DASH |
| DASH | `surge_fast`（分级最高速）恒速 `dash_dur_s`，**不检测是否撞到** | 计时到 → STOP |
| STOP | 全 0 保持 `stop_hold_s`（稳定停住） | → DONE(hit) |

丢目标沿用原阶梯：短时保持/惯性 → hold（原地全 0，`engage_hold_s`）→ 回 SEARCH；
**CENTER 段丢失绝不前进**。总时限 `comm.ball.timeout_ms`（DASH/STOP 期间不打断）。

### 5.2 过门（gate/，扁平 v1.2 设计；**逻辑图/判据见 `过门逻辑树.md`**，完整设计见 gate-PnP 文档）
- keypoint（门 + 外轮廓四角 TL/TR/BR/BL）→ `solvePnP(IPPE)`+RefineLM → 6-DoF，深度 `Z=tvec.z`；
- 门 = 闭合矩形框（红 PVC，**实测外缘 0.77×0.56 m**，管外径 5cm，悬空），前后对称无朝向要求；
- 相位机 SEARCH→RANGE_ALIGN(GOLDEN/**HDG**/CREEP/HOLD/REACQUIRE)→APPROACH→THROUGH；
    HDG=正航向（**冻结"第一次看到 4 个角点"那一帧的 ψ → 按 `turn_scale`/`max_step_deg` 限幅 →
    下行"相对角 + 编号"的旋转执行帧 → 等下位机完成反馈 → 硬停 → SWAY_BACK** 反向平移+缓慢后退等门回视野；
    **一门只下一次转向**（第一次 4 角信息最全，就信那一次、也只信那一次；不再逐小步逼近
    ⇒ `hdg.max_turns` 退化为兜底配置，见 `gate/motion/hdg.py` 与 `过门逻辑树.md` §4.3）。
    ★ **2026-10-02 换模型（板端先行、本地已对齐）**：旋转**不再由上位机 PID 闭环**（读 yaw 遥测那种），
    改为"下位机执行相对角 + 15B 遥测回 `turn_done`"：上位机只发一次、按同一编号重发、等完成、超时取消
    ⇒ **整次转向在同一帧内跑完**（自包含），上位机 yaw 恒 0；旧的方向自证/满舵保护随上位机闭环一起删除。
  **2026-09-23 修了四个症状**（转不动/转反/转过头/节拍慢），细节见 `doc/记录/2026-09-23-改动记录-review.md` §3：
  **2026-10-02 起旋转由下位机执行**：上位机只发"相对角 + 编号"、等完成反馈（不再有上位机 PID）；
  下传只给 `deg + left/right`（与 `task1_2/run_ball_reverse.sh` 同形）、顺序固定"先居中 → 达标且本帧 full → 才起转"
  （"先居中 → 达标且本帧 full → 才起转"；2026-09-30 起**没有**"航向优先"入口）、转向期间按 `comm.gate.hdg.turn_period=0.05s`（20 Hz）推进
  （`gate_task._turn_inner_loop`，与 `.sh` 路径同节拍）。
  降级链 full/p3p/width/coarse。
- **SEARCH = 左右平移扫视**（`gate.search.{sweep_s,pause_s,sway}`，波形对称来回）：
  **2026-09-20 用户定：过门过程中不允许旋转搜索**，原「旋转脉冲」已删除。
- **水平居中只有 sway 平移**（全档位一套像素门槛 `align.px_x/px_y`）：
  **2026-09-20 用户定：删除 `align_yaw.{enable,in_px,in_pose}` 及其 PID**。
  gate 里唯一的转向来源是 ALIGN.HDG 正航向（**相对角交下位机执行**；`motion.turn_pid` 的增益已不参与转向）。
- **直冲出口（任一成立即 THROUGH：只前进、不做横向微调）**：
    ⚠️ **两条出口互相独立**（2026-10-02 用户定）：`through.require_align_deg` 航向闸门**只管①**；
    ②（门口超时兜底）自己已有"在门口 + 在中央安全带内持续 N 秒"三重条件，**不再看航向** ——
    否则 width/coarse 档（没有 PnP ⇒ 永远没有 ψ）连兜底都冲不出去，会卡在门口到任务超时。
    ★ **2026-10-02 实船撞杆后收紧**：**不许"贴脸就冲"**（框占满画面时框心早已跑出画面，
      dx/dy 安全带本就失效 ⇒ "占比大"不等于"对准"）。现在的规则：
      · 当前帧**没有位姿**（coarse/width）而新鲜位姿（≤ `loiter.pose_fresh_ms`）说"已到门口（z ≤ z.cross）"
        ⇒ **不 commit**，转 **REACQUIRE 后退重取**（把门框重新看清；连续 2 次拿不回来就原地保持，宁可不冲）；
      · 信息回来（位姿恢复且 `z ≤ z.cross` 连续 2 帧）⇒ 走**正常那条 z 出口**才 THROUGH；
      · 门口兜底的**原判据不变**（占比 + |dx|/|dy| 安全带 + 连续 `timeout_ms`）。
  ① 位姿可信且 `Z≤z.cross` 连续 `z.cross_confirm_frames` 帧（**实船已验证，勿动**）；
  ② **在门口超时兜底**（`loiter.*`）：框占比 ≥ `near_ratio` 且 `|dx|≤dx_max`、`|dy|≤dy_max`
     连续超过 `loiter.timeout_ms` → 自己拍板直冲。
  ⚠️ **原②「近距丢门判过门」已按用户要求移除**：驱动相位的代码先摘掉，2026-10-01 又把残留的
  `_near_lost()`/`_fresh_z()`/`_z_ms` 与失效键 `z.near_lost_m`/`z.z_stale_ms` 一并删除。
  现在丢门 = ALIGN 防抖 hold → 超 `pose_hold_frames` 回 SEARCH；APPROACH 则 `backward_slow` 后退。
  （`z.near_lost_ratio` 仍在用：`loiter.near_ratio` 缺键时回落到它。）
  ⚠️ 旧文档里的 ③④「width/coarse 对准就直冲」**已整体删除**（2026-09-18 用户定）。
- **过门计数**：THROUGH 内按 `through.confirm_ms` **时长**计数（2026-09-18 由帧数改为时长：
  帧数语义会让冲刺时长随 fps 漂，低帧率时"冲不出去"，现场实测 900→2500ms）→ `pass+1`；
  `confirm_ms<=0` 才退回帧数语义（`confirm_frames`）。达 `pass_target` → `DONE(pass)`。
- 角点逐点融合 `gate/percept/kpt_memory.py`：**可选功能、2026-09-18 用户定默认关闭**（`enable: false`；
  板端曾因 `enable: flase` 拼写错被 `bool('flase')=True` 而实际一直开着）。
  开启用 `enable: true` 或 `AUV_GATE_KPT_MEM=1`；关闭时角点单帧直用。
- **解码后处理（2026-09-26；规范 `doc/设计/gate_pose_decode_spec.md` §4，实现 `gate/percept/gate_postproc.py`）**：
  候选阈值 `gate.det.conf`（**现值 0.5**；只作用于 gate，不动共用的 `model.score_threshold`。
  规范 §6 给的评测工作点是 0.6 —— 现值以 `cfg/vision.yaml` 为准）
  → 逐角点可信 `v ≥ V_MIN`（= `gate.keypoint.conf_thr`，0.8）
  → **四角几何合法**（顺序 + 不自交；退化的四角实例丢弃，**门框不全只降级不丢帧**）
  → **重复框去重**（小框 conf 更低 **且** ≥`postproc.min_edges` 条边重合 → 丢小框；**判据不是包含关系**）。

### 5.3 转向的两条入口（手动给角度 / 自动接受）

同一个原语 `common/motion/turn_deg.py::TurnCore`，两个入口都只做"下发相对角 + 等完成"：

| 入口 | 谁调 | 目标角从哪来 |
|---|---|---|
| **自动接受** | `gate/motion/hdg.py`（ALIGN.HDG） | 门框 PnP 测出的 ψ（**第一次看到 4 个角点那一帧**，冻结后交下位机） |
| **手动规定** | ① `python3 common/motion/turn_deg.py --deg 90 --dir left`；② `task1_2/run_ball_reverse.sh`（用 `AUV_TURN_DEG/AUV_TURN_LEFT` 传角） | 命令行/环境变量**人工给的度数** |

- 手动入口**只暴露三个参数**（用户 2026-10-02 定）：`--deg`（角度，正数）、`--dir left|right`（左=负角、右=正角）、
  `--timeout`（等完成秒数）。**其余运动参数一律归下位机** —— 上位机只发"相对角 + 编号"，
  所以旧的 `--out-max/--yaw/--kp/--ki/--kd/--deadzone-deg/--norm-deg/--imag-sign` **不再接受**（传了直接报错），
  `task1_2/run_ball_reverse.sh` 里对应的 `AUV_TURN_*` 旋钮也一并删除。
- 退出码：`0` = 下位机回报完成；`3` = 等完成超时（下位机没回 `turn_done`）；`5` = 下发失败/中止。

## 6. 串口协议（下发 11B / 旋转执行帧 / 上行 15B，与下位机对齐）

```
下发: 0xA5 | axis0..axis6 | btn0..btn2
axis0=yaw axis1=surge axis2=heave axis3=sway（中位128，极性>128 正向）
任务 → DOF → comm.yaml dof_map → 轴字节（ramp 平滑）；心跳≥20Hz；急停=中位锁定

上行: 0xAA 0x55 | depth_cm | target_cm | roll_cd | pitch_cd | yaw_cd | checksum
      (int16 小端 ×5，从 byte3 起；checksum = sum(前13B) & 0xFF；见 base/hw/telemetry.py)
```

**限深保护（base 层唯一一处，任务不感知）**：每次发帧前读空接收缓冲 → 最新深度；
`comm.depth_guard` 判定 `depth ≤ min_depth_m`(默认 0.3m) 时本帧**禁止上浮**
（heave 清零 + heave 轴当帧回中 `snap`），surge/sway/yaw 原样——保护不干扰对准/前进；
遥测缺失或超时(`stale_ms`)按 `stale_action` 处理：`pass`(默认)放行 / `block_up` 连盲上浮也不许
（SIM 无串口始终放行）。手动模式(udp_server 键盘遥控)同样受此限制。

## 0. 记号

| 记号 | 含义 |
|---|---|
| `P:` | 位姿档 `full` / `p3p`（有 PnP 位姿，能测 z 与航向） |
| `W:` | `width` 档（对向 2 角：只有测距 + 水平中点） |
| `C:` | `coarse` 档（只有整框：只有框心 + 占比） |
| ★ | **保命闸**（不许为了让过门更容易而放宽） |
| ▲ | **已移除 / 曾经的坑**（保留说明是为了让读旧文档的人知道哪些说法作废，见 §7） |

**位姿有效性**（`gate/percept/geometry.py:230` `gate_pose`，调用点 `gate_task.py:280`）
```
候选生成
├─ ≥4 点（共面矩形）→ solvePnPGeneric(IPPE) 取全部解
│     └─ 全为 nan/异常 → SQPNP → 再退 ITERATIVE(带上帧猜值)
└─ 恰好 3 点        → 必须有上帧猜值 prev（P3P/ITERATIVE + guess）；**没有 prev 的 3 点不可信**
过滤
├─ _finite：丢 nan/inf（门正对等退化配置下 IPPE 会给 nan 解）
├─ 重投影 RMS(px) > [pnp.reproj_px=20] → 丢
├─ z 不在 [pnp.z_min=0.2, pnp.z_max=15.0] → 丢
├─ 双解消歧：平面目标有前后对称双解、RMS 接近 → **用 prev（上帧位姿）挑帧间连续的那个**
└─ refine=[pnp.refine=true] → solvePnPRefineLM 精调
→ 全部候选都不合格 ⇒ 返回 None ⇒ 上层降级（见 §5.1）
```

**航向误差 ψ 的定义**（`geometry.py:302` `gate_normal_angles_deg`）
```
n = R·[0,0,1]（门法向，相机系；n_z<0 时翻到朝相机那侧）
psi_deg = atan2(n_x, n_z)
   + = 门法向偏画面**右** = 机身相对门**左偏**
   − = 门法向偏画面**左** = 机身相对门**右偏**
帧间噪声 p50≈3°，EMA(0.4，≈4 帧) 后 ≈3° ⇒ 够"慢慢校"，不够快速闭环
只有 mode == full 的帧才更新 ψ（p3p 欠定：重投影残差恒 0、深度偏 −28%、航向 std 64~69°）
```

## 3. 相位机总览

```
   入口：开机 / `_start_search()`（换门：清空门内状态，`_pass_cnt` 保留）

   SEARCH ──看见门(P/W/C 任一档)──► ALIGN ──居中达标 且 不需再转──► APPROACH ──► THROUGH
     ▲                               │                                          │
     │                               │                                          └─ 计时到 [confirm_ms=3000]：
     │  子状态（按"信息量 + 是否已转过"仲裁）                                       · pass < [pass_target=4] → 回 SEARCH 找下一门
     │    GOLDEN     位姿/框对准，攒"居中确认"                                     · pass ≥ pass_target  → _finish("pass") → DONE
     │    HDG        正航向：冻结 ψ → 转一次 → 硬停
     │    SWAY_BACK  转后反向平移 + 缓慢后退（等门回视野）
     │    CREEP      对准但还远：慢速靠近（换取角点）
     │    HOLD       停住：等位姿恢复 / 放弃窗口到期 / 帧间防抖
     │    REACQUIRE  后退重取（角不足 / 门装不下）
     │
     └── 丢门超 `pose_hold_frames`(_tick_lost) 或 REACQUIRE 退满 `max_ms` ── 回 SEARCH
```

## 4. 普通流程：逐相位 / 逐子状态

### 4.1 SEARCH — 左右平移扫视（**不许旋转**）

```
_search_sweep（channels.py:108）  方向约定：+ = 右移；[gate.search.sway=0.6]
一轮 = 右 sweep → 停 pause → 左 sweep → 停 pause；**每轮 sweep 时长 ×2，上限 sweep_max_s**

 段0 右移 (+0.6) │ 段1 停 (0) │ 段2 左移 (−0.6) │ 段3 停 (0)

轮次 k   每段 sweep_k                一个周期 2×(sweep+pause)
 0        2.0 s  = sweep_s           6.0 s     ┤0────2──3────5──6
 1        4.0 s                    10.0 s            ┤6────────10─11───15─16
 2        8.0 s                    18.0 s                     ┤16──────────24─25─────33─34
 3       16.0 s                    34.0 s
 4+      32.0 s = sweep_max_s      66.0 s
[sweep_s ≤ 0] → 只停不扫（= 原地待机）
整轮扫视是**等时长对称**的 ⇒ 净位移 ≈ 0（防一路漂到池壁）
```

进入 SEARCH 时 `_start_search()`（channels.py:84）重置：`_post_sway*`、ψ/EMA/转向计数/`_hdg_done`、
重锁基准、`_search_entry_ms`、`_last_pose`、`_z_last`、`_z_guard`、`_cross_cnt`、`_lost_cnt`、`_hold_cnt`、
`kpt_memory.reset()`。**不动 `_pass_cnt`**（已过门的计数是要留的）。

### 4.2 ALIGN 的三条并列入口

**① 位姿档 `_on_pose`（modes.py:19）** —— 居中**只用像素**，一套 PID 全档位共用
```
输入：P: full / p3p 的 (rvec,tvec)
├─ _relock_guard(z)：与丢门前的 z 差 > [z.relock_z_jump_m=0.5] → 判"另一个门" → hold（不接收、不改基准）
├─ 更新 _last_pose / _z_last ；_reacquire_cnt = 0   （`_z_ms` 已随死代码删除，现在只有 `_z_last`）
├─ 门原点(0,0,0) 用位姿投影回图像 → (c[0],c[1])  ← 比四角均值准（p3p 缺角也对）
│     dxn = (c[0] − W/2)/(W/2)     正 = 门在画面右 → sway 取正
│     dyn = (c[1] − H/2)/(H/2)     正 = 门在画面下 → heave 取负
├─ mode == FULL → ψ = gate_normal_angles_deg() → EMA0.4 → _hdg_deg / _hdg_ms
├─ sway = PID_sway(dxn) ；heave = −PID_heave(dyn) ；★yaw ≡ 0（居中不用 yaw）
├─ aligned = |dxn| ≤ [align.px_x=0.20] 且 |dyn| ≤ [align.px_y=0.25]
│
├─ z ≤ [gate.z.cross=1.2] ？（穿门判据，见 §4.2）
│   ├─ _cross_cnt++ ；need = [z.cross_confirm_frames=2]
│   ├─ _cross_cnt ≥ need 且 _start_through() 成功 → action=through（surge=0.6）
│   └─ 否则 → action=center（**冲刺前最后一帧只做横向微调**；被航向闸门拦下也走这里）
│   └─ return
├─ 否则 _cross_cnt = 0
│
├─ phase == SEARCH → phase=ALIGN，substate=GOLDEN，_center_cnt=0
└─ phase == ALIGN
    ├─ substate = GOLDEN
    ├─ _loiter_commit(dxn,dyn,占比) 命中 → return（§5.5）
    ├─ aligned ？
    │   ├─ 是 → _center_cnt++
    │   │        └─ ≥ [align.confirm_frames=2] ？
    │   │            ├─ _hdg_ready() → _hdg_start(now,"golden") → action=hdg   （§5）
    │   │            └─ 否 → _note_hdg_skip(原因) → phase=APPROACH            （§4.3 六种原因）
    │   └─ 否 → _center_cnt = 0
    └─ action=center（sway/heave + hdg 诊断字段）
```

**② width 档 `_on_width`** —— 只有测距 + 中点
```
├─ _tick_hdg_degraded() → 转向中则本帧只推转向，return
├─ z = fx·W/|Δu|（宽 W 用 [gate.geometry.frame_w=0.7]）；算不出 → 转 _on_coarse
├─ z = clip(z, 0.2, 15.0) → 写 _z_last
├─ aim_x = (u1+u2)/2 → dxn ；dyn 用**整框中心** y
├─ aligned = |dxn| ≤ 0.20 且 |dyn| ≤ 0.25（与位姿档同一套阈值）
└─ phase == ALIGN
    ├─ _loiter_commit 命中 → return
    ├─ aligned 且 z > [gate.width.z_max=1.5]  → substate=CREEP，_center_cnt++，
    │                                           surge=[surge.creep=0.20]
    │        └─ _center_cnt ≥ [align.confirm_frames=2] → phase = APPROACH
    └─ 否则 → substate=HOLD，surge=0
    动作 = creep（surge>0）或 hold
    ★ 上面整块都在 `if phase == PH_ALIGN:` 里 ⇒ 一旦升到 APPROACH 就**整块不生效**：
      creep 不给 surge、loiter 也不再兜底，只剩 sway/heave 原地对中，
      直到整门丢失（`_tick_lost`）或任务超时。语义与取舍见 §7.2。
```

**③ coarse 档 `_on_coarse`（modes.py:178）** —— 只有整框，**没有测距**
```
├─ _tick_hdg_degraded() → 转向中则只推转向
├─ （没有测距：**不动 `_z_last`**，日志/重锁守卫还要看它实际是多少）
├─ ratio = det.w / 帧宽
├─ phase==ALIGN 且 substate==REACQUIRE → _tick_reacquire(now, ratio)  （§5.4）
├─ dxn/dyn 用整框中心；aligned 用 [coarse.align_x=0.33] / [coarse.align_y=0.29]（**刻意比位姿档松**）
├─ phase==SEARCH → ALIGN ；phase==APPROACH → **退回 ALIGN**（角全失时保守降级，不盲冲）
└─ phase == ALIGN
    ├─ _loiter_commit 命中 → return
    ├─ aligned → substate=CREEP，_hold_cnt=0，surge=0.20（**对准就靠近，争取露出角点**）
    ├─ ratio < [coarse.far_ratio=0.18]        → 远距小框：只对中（action=center，surge=0）
    ├─ ratio ≤ [coarse.near_ratio=0.55]       → 中距：substate=HOLD，_hold_cnt++
    │        └─ _hold_cnt ≥ [hold.max_frames=20] → _enter_reacquire()
    ├─ 在"放弃后退"窗口内（_give_up_until_ms）  → substate=HOLD（等位姿恢复或窗口过期）
    └─ 近距装不下且没对准                       → _enter_reacquire()
```

### 4.3 ALIGN.HDG — 正航向（先居中 → 再转，**没有"航向优先"入口**）

```
   GOLDEN ──居中达标 且 有"转向后的新 ψ"──► TURN ──收口──► 收尾(同一帧) ──► SWAY_BACK ──► 交回视觉
                                                                                        │
   ┌────────────────────────────────────────────────────────────────────────────────────┘
   └─ 仍有残余 ψ 且 未达 [hdg.max_turns=5] ⇒ 再走下一小步（**逐小步逼近，没有"只转一次"**）

   各段内部逻辑
   ─────────────────────────────────────────────────────────────────────────────────────
   GOLDEN → TURN   `_hdg_start(now, "golden")`（hdg.py:412）
       · 冻结本帧 ψ = `_hdg_deg`（EMA 后的 full 帧值）
       · 方向：左/右 = (ψ < 0) ? 左 : 右        ← 2026-09-30 取反，见 §7.3
       · 幅度：deg = |ψ| × [hdg.turn_scale=0.8]，再被 [hdg.max_step_deg=15°] 钳位（0 = 不设限）

   TURN（SUB_HDG）
       ★ 整条视觉链路被绕开：不检测、不 PnP、丢门/档位退化都**不中止**（§5.7）
       闭环 = TurnCore(deg, left)：遥测 yaw + PID，20 Hz（[motion.turn_pid.period=0.05]）
       收口 = 6 种终态之一（§5.8）

   收尾（`_turn_blocking`，全在**同一帧内**完成）
       ① `_hdg_turns++`（本门第几次）；substate 回 GOLDEN；`_center_cnt = 0`（转向动了门在画面里的位置）
       ② 硬停 `stop_hard`（[hdg.stop_hard=true]）：帧内连发中性帧 + 遥测校验
       ③ **时钟折算**：把"转向 + 硬停"的真实流逝补进 `_now_ms` ⇒ 平移窗口从真实时刻起算
       ④ `_hdg_turns_last_ms` = 真实时刻   ← 判"有没有新的 ψ"的基准
       ⑤ `_start_post_sway()`

   SWAY_BACK（主循环里的一个状态，靠 `_set_info` 覆盖实现）
       sway  = −(转向方向) × [hdg.post_sway=0.20]     （左转 → 右移）
       surge = −[hdg.post_sway_back=0.15]             （同时慢慢退一点）    heave = yaw = 0
       退出 ① 当前门的可信角点数 ≥ [hdg.post_sway_kpt_min=2] → 交回视觉
            ② 窗口到期 [hdg.post_sway_ms=600]        ← 安全兜底，绝不永久停摆
            ③ 让位：action==through 或 转向进行中（平移优先级最低）
```

**转向能不能起（`_hdg_ready` / `_hdg_skip_reason`，hdg.py:403 / 215）**
```
_hdg_ready = 启用 且 本门未收口 且 未达 max_turns 且 ψ 是"上次转向结束之后"测到的
居中达标却没起转 → 写 last_info["hdg_skip"] + 终端报一次（每门一次）：
    off(未启用) ／ done(本门已收口) ／ no_psi(还没测到过 full 帧) ／
    turns_full(已达上限 N 次) ／ wait_psi(等转向之后的新 ψ) ／
    psi_ok(其实可以转 —— 出现它就说明是居中没达标，不是航向的问题)
```

### 4.4 APPROACH — 两档前进（仍修 sway/heave）

```
_on_pose 里（位姿档）：
   surge = [motion.surge_fast=0.35]  if z > [gate.z.slow_max=1.3]
           [motion.surge_slow=0.15]  else
   动作名 = forward_fast / forward_slow
   sway/heave 照常修正（容差随距离变大不会失控）
[gate.z.fast_max / z.align_max 当前**未参与运算**，留作三档扩展]
```

### 4.5 THROUGH — 只前进、不微调

```
_start_through()（exits.py:11）—— 两条入口共用，**必须先过航向闸门**
├─ ★闸门：[through.require_align_deg=8.0] > 0 且 _hdg_deg 非 None 且 |_hdg_deg| > 阈值
│        → 拦下：不进 THROUGH，写 last_info["through_block"]，留在原相位继续对准
│        （从没测到过 ψ → 放行：没得判）
├─ 通过 → _hdg_abort("进入冲刺")（若正在转则中止）
├─ phase = THROUGH；清 _lost_cnt / _z_guard / _through_start_ms / _loiter 计时
└─ **重置两套横向 PID**（_reset_lateral_pids）

_tick_through()（exits.py:46）
├─ 发 surge = [gate.surge.through=0.60]，sway/heave/yaw ≡ 0
├─ 结束判据优先**时长** [through.confirm_ms=3000]（≤0 才退回帧数 [confirm_frames=8]）
└─ 到时 → _pass_cnt++
      ├─ < [gate.pass_target=4] → _start_search()（找下一个门）
      └─ ≥ pass_target        → _finish("pass") → DONE
```

## 5. 特殊应对（异常 / 退化）：逐条

### 5.1 位姿被拒或跳变 → 降级

```
mode ∈ {full,p3p} 但 gate_pose 返回 None（RMS 超限 / 非有限 / z 越界 / 无谓消歧失败）
   └─ mode := coarse  ★**跳过 width**：4 角都在却解不出位姿时，不再假装能用 2 角测距
   └─ _z_guard = False、_cross_cnt = 0（★清掉"连续就近"的进度，防单帧错解攒出冲刺）
   └─ mode 变了 → _center_cnt = 0（跨档不接"假连续"）
z 跳变（上帧有可信位姿）：|Δz| > [pnp.max_z_jump_m=0.8] → 本帧位姿作废 → 同上降级
   ★为什么：平面 PnP 偶发错解若给出 z ≤ z.cross，会直接触发满速冲刺
```

### 5.2 整门丢失（`det is None`）→ `_tick_lost`（exits.py:97）

```
通用：_lost_cnt++ ；_z_guard = False ；_cross_cnt = 0
      首次丢失时记下重锁基准：_relock_z_ref = _z_last、_relock_ratio_ref = 当时的框占比
pose_hold = [gate.pose_hold_frames=10]

├─ phase==ALIGN 且 substate==REACQUIRE → _tick_reacquire(now)（无 ratio ⇒ 只按时间退完）
├─ phase==ALIGN
│   ├─ SWAY_BACK 窗口还活着 → action=sway_back（继续把门拉回视野）
│   ├─ _lost_cnt ≤ 10 → action=hold（**帧间防抖**：沿用上一帧的居中，别乱动）
│   └─ 超窗 → _start_search() + action=search
├─ phase==APPROACH
│   ├─ _lost_cnt ≤ 10 且 _z_last 非空 → action=backward_slow（surge=−[surge.lost_backward=0.20]）
│   │     ★轻微后退换回锁定/更大视野，**不是**直行盲冲
│   └─ 超窗 → SEARCH
└─ phase==SEARCH → 扫视波形（§4.1）
▲「近距丢门 = 已过门 → 直冲」这条出口**已从代码与 cfg 一并摘除**（死代码也已删；见 §7.1）
```

### 5.3 丢门后"重锁到另一个门"的保护（两套）

```
① 有位姿时 _relock_guard(z)（modes.py:312）
     丢门时记 _relock_z_ref；重锁那一帧若 |z − ref| > [z.relock_z_jump_m=0.5] ⇒ 判"后面那个门"
     → **拒收该帧位姿**、本帧 action=hold（等真正的门回来）；同一个门则解除保护
② 没位姿时 _relock_guard_ratio()（modes.py:331）
     丢门时记 _relock_ratio_ref；本帧占比 < [z.relock_far_ratio=0.7] × ref ⇒ 同样判"另一个门"
     → action=hold，不朝它靠近
   场景：正要冲刺时被水波推一下 → 丢门 → 若先认出的是**后面那一个门**，
        直接锁上去就会一路越过当前门
```

### 5.4 角不足 → 后退重取 REACQUIRE（modes.py:253 / 289）

```
_enter_reacquire（进入）
├─ 距上次真后退 ≥ [reacquire.reset_after_ms=3000] → 计数清零（一次倒影干扰不该永久锁死）
├─ _reacquire_cnt++
├─ 超过 [reacquire.max_times=2] ？
│   ├─ 是 → ★**放弃后退**，改 substate=HOLD、_give_up_until_ms = now + 3000ms
│   │        （倒影持续干扰时"退-进-退"会来回震荡；退几次没用就别退了）
│   └─ 否 → substate=REACQUIRE，记 _reacquire_start 与 _reacquire_ratio0（进入时的框占比）
_tick_reacquire（推进，**闭环**，不再固定退满）
├─ ratio ≤ ratio0 × [reacquire.stop_ratio=0.75] → 退够了 → substate=HOLD，回对准
├─ 已退 ≥ [reacquire.max_ms=800] → _start_search()（换门）
└─ 否则 → action=reacquire，surge = −[surge.reacquire=0.25]
```

### 5.5 门口的"卡住"兜底 `_loiter_commit`（exits.py:142）

```
不看档位，三个条件**同时**成立才计时（任一不成立就重新计时）：
  ① 框占比 ≥ [loiter.near_ratio=0.60]（缺键回落到 [z.near_lost_ratio=0.50]）
  ② |dxn| ≤ [loiter.dx_max=0.14]     ③ |dyn| ≤ [loiter.dy_max=0.20]   ← 安全带
  以上连续 ≥ [loiter.timeout_ms=3000]
→ 调 _start_through()
   ├─ 航向闸门拦下 → **不算 commit**（返回 False，门口计时保留，下一帧再评）
   └─ 放行 → action=through（surge=0.60）
现场依据：门口 creep 了 18.7 s，最后只靠"丢检"补一次 1.3 s 冲刺，没冲出去
```

### 5.6 任务级终局与"下一门"

### 5.7 转向期间的隔离（关键行为）

```

   假时钟（用例）→ 退化成"每相机帧一步"，测试不会被拖成真时间
```

### 5.8 转向的 6 种收口（`TurnCore.step`，common/motion/turn_deg.py:239）

```
DONE      到位 —— 两条判据**任一**成立、且**连续 3 帧**都成立才收：
            ① 残余误差 |err| ≤ [turn_pid.deadzone_deg=6°]        （未转够的那一侧由它管）
            ② 0 ≤ done_deg − 下发 deg ≤ [turn_pid.overshoot_tol_deg=10°]  （**超转容差窗**）
           ⇒ HeadingAligner 置 DONE：本门正航向收口
TIMEOUT   起转至今 > [gate.hdg.turn_timeout_s=8.0 s]
           ⇒ 判"舵效不足 / 卡住 / 增益过小" → aligner 转 GIVEUP（带残余航向继续走，不卡死）
ABORTED   四种原因（`TurnCore.why`）→ aligner 转 ABORTED（本门不再尝试）：
  · no_tel   一直没有遥测 yaw，超过 3.0 s ⇒ **拒转**（闭环量缺失时一根舵都不发）
  · div      **方向自证**失败：已朝目标方向施加 ≥ 0.3 DOF·s（≈1 s 满舵），遥测却显示朝**反方向**
             转了 > [turn_pid.div_deg=15°] ⇒ 停转
             查：dof_map.yaw.sign / comm.telemetry.yaw_sign / 推进器接线
  · sat      **满舵保护**：|out| ≥ 0.9×out_max 连续 ≥ [turn_pid.sat_max_s=2.0 s]，而这期间
             "|err| 改善"与"朝下发角推进"都 < [turn_pid.sat_progress_deg=5°] ⇒ 立刻停转；
             若已进"超转容差窗"则不掐（轻微超转不算没进展）
  · external 外部中止：estop(Ctrl-C) / `_start_through()` 的"进入冲刺"
             （旧版还有"整门丢失"，现在**已移除** —— 转向期间根本不看画面，见 §5.7）
```

> 这三条（no_tel / div / sat）都是**兜底闸**，只回答"船有没有按命令动"，不测量符号（σ 在 `yaw_sign()` 里算死）。


## 6. `mode` × `action` 对照表（含实际 DOF）

`_set_info` 是全任务**唯一的 DOF 下发口**（channels.py:24 → `uart.send_dof(surge, sway, heave, yaw)`；
另有两个不经它的出口：`_finish` / `process` 的 `uart.neutral()`、`_stop_hard_framed` 的 `uart.stop_hard()`）。
`sway` 一律来自 `PID_sway(dxn)`，`heave` 一律来自 `−PID_heave(dyn)`（**全档位共用一套像素 PID**；
增益缺省走 `comm.motion.pid_sway / pid_heave`：kp8.0 ki0.01 kd0.05 out_max0.55 dz0.05 / kp1.0 ki0 kd0.15 out_max1.0 dz0.04）。

| action | surge | sway | heave | yaw | 谁发的 | 语义 |
|---|---|---|---|---|---|---|
| `search` | 0 | 扫视波形 ±[0.6]/0 | 0 | 0 | `_tick_lost`(SEARCH) | 平移扫视找门 |
| `center` | 0 | PID(dxn) | −PID(dyn) | 0 | 位姿/width/coarse | 对准；**只对中不前进** |
| `hold` | 0 | 视调用点：0 或 PID | 同左 | 0 | 多处 | 停住等条件（见下注） |
| `creep` | +0.20 | PID | PID | 0 | 对准但还远 | 慢速靠近换角点 |
| `hdg` | 0 | 0 | 0 | ±[turn_pid.out_max=0.30] | `_hdg_start` / `_turn_inner_loop` | 正航向转向 |
| `sway_back` | −0.15（后退） | ∓0.20（转向反方向） | 0 | 0 | `_set_info` 覆盖 | 转后把门拉回视野 |
| `forward_fast` | +0.35 | PID | PID | 0 | 位姿档 APPROACH（z > 1.3） | 远距进近 |
| `forward_slow` | +0.15 | PID | PID | 0 | 位姿档 APPROACH（z ≤ 1.3） | 近距进近 |
| `through` | +0.60 | 0 | 0 | 0 | 两入口 | 冲刺，不微调 |
| `backward_slow` | −0.20 | 0 | 0 | 0 | `_tick_lost`(APPROACH) | 丢门防抖后退 |
| `reacquire` | −0.25 | 0 | 0 | 0 | `_tick_reacquire` | 后退重取整门 |
| `stop` | 0 | 0 | 0 | 0 | 初值 / `_finish` | 中性帧 |

> **`hold` 不是一种行为，是四种**（DOF 不同，排查时要看调用点）：
> ① 重锁拒收 / REACQUIRE 放弃 / 退够 / ALIGN 丢门防抖 → **sway=heave=0**（彻底停）；
> ② coarse 中距等待、coarse 非 ALIGN、放弃窗口 → **保持** sway/heave 修正。
> 日志里 `action` 相同但船动的不一样时，先看是哪一条。

## 7. 曾经的坑 · 现在的语义（▲ = 已移除）

> **代码与注释不一致时以代码为准。** 本节 7.1/7.6 的条目是本次读码发现、并已在 2026-10-01 处理掉的；
> 保留它们是为了让读旧文档/旧日志的人知道**哪些说法已经作废**。

**7.1 「近距丢门判过门」这条冲刺出口曾经存在，现已移除（重要）**
- 现在冲刺只有**两条入口**：① `z ≤ z.cross` 连续 `cross_confirm_frames` 帧；② 门口 `loiter` 超时兜底。
  两者都要过 `through.require_align_deg` 航向闸门（`_start_through()` 的两个调用点）。
- 曾经的 ②「近距（`z ≤ z.near_lost_m` 或 占比 ≥ `z.near_lost_ratio`）丢门 = 已过门 → 直冲」：
  代码里早已不驱动相位（测试 `test_align_near_lost_falls_back_to_search` 的注释注明"按用户要求移除"），
  **2026-10-01 把残留的死代码一并删掉**：`_near_lost()`、`_fresh_z()`，以及 `_z_ms`（变成只写不读）、
  cfg 键 `z.near_lost_m` 与 `z.z_stale_ms`。
- **现在丢门的行为**（§5.2）：ALIGN → 防抖 `hold`，超 `pose_hold_frames` 回 SEARCH；
  APPROACH → `backward_slow` 轻微后退，超窗回 SEARCH。**不判过门、不直冲。**
- 仅存的"在门口"信号：`z.near_lost_ratio`（loiter 的 `near_ratio` 缺键时回落到它）。
- 真正防"丢门后冲不出去"的手段是**让 THROUGH 更早触发**（`z.cross` / `cross_confirm_frames`），
  因为 `_step` 里 `phase == THROUGH` 的判断**在 `det is None` 之前**。

**7.2 `width` 档升到 APPROACH 之后只原地对中（代码已明示为本档语义）**
- `_on_width`（modes.py）只有 `phase == PH_ALIGN` 分支才给 surge（creep 0.20）；APPROACH 走函数尾部
  `_set_info("center", …)` ⇒ **surge 缺省 0**，只发 sway/heave。
- 可达路径：`aligned 且 z > width.z_max=1.5 → creep → 攒够 align.confirm_frames(=2) → APPROACH`，
  而 z 仍 > 1.5 时后续帧还是 width ⇒ 此后**不再前进**。
- ⚠️ 而且 creep 与 `_loiter_commit` **两个出口都在 `if self.phase == PH_ALIGN:` 块内**，
  对 APPROACH 相位**都不生效**（旧注释写的"同样生效"与代码不符，2026-10-01 在代码里更正）
  ⇒ 这一段只能由**整门丢失**（`_tick_lost`）或**任务级超时**（180 s）结束。
- 想让它在 APPROACH 也能推进，要么让位姿档恢复（`_on_pose` 的 APPROACH 才有 fast/slow），
  要么把 creep/loiter 提到相位判断之外 —— **两种都改行为，需用户拍板**。

**7.3 ψ → 转向方向：读旧文档/旧日志必须知道映射反过**
- `gate/motion/hdg.py`：`left = bool(psi < 0)`（**psi<0 ⇒ 左转，psi>0 ⇒ 右转**）；
  同处注释记载 2026-09-30 现场发现旧映射（psi>0 ⇒ 左转）**转反了**，故取反。
- 与门法向定义（`geometry.py::gate_normal_angles_deg`：`+ = 门法向偏画面右 = 机身左偏`）自洽：
  机身右偏（ψ<0）→ 左转修正。
- 结论：**2026-09-27 及之前的 ψ→方向映射是反的**，用那时的日志复盘会得出相反结论。

**7.4 仍在的"非缺陷但要知道"**
- `_on_pose` 末尾的 `else` 分支不可达（THROUGH 已在 `_step` 截走）。
- `gate.z.align_max` / `gate.z.fast_max` 不参与运算（cfg 注释已说明，保留作三档扩展）。
- `gate.motion.turn_pid` 里的 `sat_*` / `overshoot_tol_deg` 只在转向闭环用（见 §5.8），不影响居中。

**7.5 结构提示：设计仍是"扁平 v1.2"，代码按方法簇拆成两个包**
- **设计血统没变**：仍是扁平 v1.2（**没有** v1.3/v1.4 分层 gate）；变的是**代码组织**：
  `gate/percept/`（检测/解码/后处理/几何/前端/mock）+ `gate/motion/`（档位/出口/通道/正航向/常量）
  + `gate/gate_task.py`（只有编排：`__init__`/`reset_state`/`process`/`_step`/`_finish`/`ready`）。
- 于是**旧文档里的行号与"单文件一百多行逻辑树"都过时**；本文按函数名索引。
- 米制 PID 与"米制/像素两套阈值"已删：**只有一套像素 PID + 一套像素阈值**（`align.px_x/px_y`）。

**7.6 2026-10-01 已修掉的（改代码时不必再找）**

- `gate/gate_task.py` 模块 docstring 的「直冲出口三条」→ **两条**；`main.py` docstring 的

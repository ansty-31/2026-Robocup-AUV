### 0.1 方法论：什么时候用棋盘 / 靶子 / 门框（2026-09-23 定）

三种工具各管一段，**别拿一个去替代另一个**：

| 工具 | 唯一能给的东西 | 成本 | 不能给 |
|---|---|---|---|
| **棋盘格标定**（空气 + 水各一次） | **内参的全部**：`fx/fy/cx/cy/D` + RMS 验收；顺带把 **`k = fx_water/fx_air` 直读出来** | 各 ~10 min（喂图即可，`calibrate_camera.py`） | `W_eff`（门角点口径）、深度链路真值、符号/约定、安全裕度 |
| **卷尺刻度靶子**（`tape_ticks.py` / `ruler_calib.py`） | **现场无板巡检**：3 张照片量 `fx`（±0.6%）；`c ≈ 0`（距离口径）的独立检查 | 1 min | 主点、畸变系数、`W_eff` |
| **门框 dump**（少量档位，手标 + 检测器） | `W_eff` ⇒ `frame_w/h`；**深度通道端到端真值**；`psi ≈ −yaw`、`t_x/t_y` 符号；`reproj_px`/`conf_thr` 的取舍点 | 岸/水各 ~15 min | 内参（它本身依赖内参） |

**一条原则**：「**相机**」用棋盘；「**漂移巡检 / 没带板的现场**」用刻度靶子；「**物体口径 + 链路 + 约定**」必须用门。

**陆上那套的历史定位（别误读成白做）**：当时没有打印棋盘，所以用卷尺刻度当靶子替代内参标定；
它的真正战功是**拿卷尺量过的真距离去卡 PnP 输出**，得到稳定的 `z/z_true ≈ 0.70`
⇒ 用空气侧两个独立方法（1075.2 / 1111）替换配置值后变成 **0.96** ⇒ 判定"配置 fx 错了 1.37 倍，不是介质差"
⇒ 触发 §B4 的证伪条款 ⇒ 才有 2026-09-23 这份正确的**水下标定**（§B4c）。
**没有它，782.5 会一直被当成有效内参**（所有米制阈值偏 24%，且没有任何数据会报警）。

**现状与遗留（2026-09-23）**：
- 水下：已是棋盘标定（`runs/calib_auv5/`，fx=1207.6、RMS 0.546 px）⇒ **内参这一半以后一律用棋盘**；
- 空气：`front_camera_air.yaml` **只量了 fx**（1078），`cx/cy` 是从旧水下那份**抄的**（与新的差 +52.5/+20.3 px
  ⇒ 岸上 `t_x` 绝对量在 1.5 m 处约偏 **7.3 cm**）、`D` 是**故意写 0**（不是量的）⇒ 建议用棋盘补一次；

## 1. 原理与符号约定

### 1.1 深度标尺关系（本实验的核心）

4 角 PnP 的 `tvec.z` 是"用**配置里的门框尺寸**和**配置里的内参**去解释图像上量到的门框像素尺寸"得到的距离。
正对门（门平面与像平面平行）时：

```
Δu = fx_med · W_true / z_true       （真实成像：fx_med = 该介质下的等效焦距）
z_meas = fx_cfg · W_cfg / Δu        （PnP 用配置值反解）
⇒ z_meas = z_true · (fx_cfg / fx_med) · (W_cfg / W_true)
                     └─ k_med ─┘        └─ 门框口径 ─┘
```

⚠️ **两个因子在"只看门框"时是简并的** —— 一个比例、两个未知量。分开的唯一办法是**物理靶子**
（已知长度的卷尺刻度，§A0b 空气侧 / §B4 水下侧）：靶子给出的 `fx_med` 与门无关。

**2026-09-22 已确定的事**：`cfg/front_camera.yaml`（fx=782.5）= **装了罩、在水里**标定 ⇒ `fx_water = 782.5`
（待 §B4 复核）。

> 🔴 **2026-09-23 更正（本节以下结论请以 §B4b/§B4c 为准）**：那份 782.5 已被**水里棋盘标定**取代 ——
> 现在在用 `fx_water = **1207.6**`（`runs/calib_auv5/`，RMS 0.546 px，83 视图）。
> ⇒ 下面"岸上 0.70 是介质差（`k_air≈0.70`）"的解释**作废**：`0.70` 主要来自 fx 错了 1.37 倍；
> ⇒ 水陆关系是 `k = fx_water/fx_air ≈ 1207.6/1078 = **1.12**`（不是 1.37~1.42）；
> ⇒ **米制阈值的含义整体变了**（同一批数字现在对应"真的那几米"），清单见 §B4c ③。

（以下为 2026-09-22 旧记录；`k_air` 这个「介质差因子」已作废，保留仅为留痕）岸上（空气）实测 `fx_air ≈ 990~1200` ⇒ **岸上四档的 `a≈0.70` 里天然含 `k_air = fx_cfg/fx_air ≈ 0.70`，
不是门宽标尺错**。所以：

```
① 先靶子法量 fx_med（与门无关）      §A0b（空气）/ §B4（水）
② 再用门的 Δu 反解真实门宽：W_true = Δu·(z_tape + c) / fx_med
③ 只有 ② 才允许回填 geometry.frame_w/frame_h
```

⚠️ **顺序不能倒**：先回填 `frame_w` 去凑 `a≈1`，等于把介质因子塞进门框尺寸，
换介质/换相机时必踩（这也是这份文档 09-22 白天的思路，现已纠正）。

## 2. 器材与场地布置

| 器材 | 用途 | 备注 |
|---|---|---|
| 卷尺（≥5 m）+ 夹子/重物 | 深度真值 | **最重要**；零点定义见下 |
| 地面刻度胶带 / 粉笔 | 横向真值 `lat`、船位复现 | 每 25 cm 一道 |
| 转台/转椅（带角度刻度）或地面角度线 + 激光笔 | 航向真值 `yaw` | 台架阶段比让船自己转更准 |
| 垫块（书/木块，先量厚度） | 竖向真值 `up` | 或让门在挂轨上上下移 |
| 水平尺 | 把光轴调平、门调竖直 | 减少多余的 `pitch` 分量 |
| 记号笔 + 本文 §6 记录表 | 现场记录 | 文件名与真值一起写 |
| **水下**：标尺杆 / 卷尺（可在岸上先标好长度） | 水下深度真值 | 水里读数慢，先把杆长标好、只记"第几档" |
| **水下**：擦镜布 + 干燥剂 | 防镜头起雾/水渍 | 起雾的现象像"模型坏了"，一票否决整轮数据 |
| **水下**：可以压住门的配重 / 池边固定点 | 让门不随水漂 | 门漂了 = 真值没了 |

**真值零点怎么定**（必须全组统一，否则会拟合出假偏置）：

- `z_true`：从**门管中心平面**量到**相机镜头外壳标记**。镜片与后节点差 1~2 cm，
  统一口径后它是一个**常数偏置**（会体现在拟合的 `b` 里，可解释、可接受）。
- `lat_true`：门中心到**相机光轴**的横向距离。做法：先把船摆到"门在画面正中"
  （`preview_detect.py --gate-kpt` 看 `dxn≈0`），在地面沿四角画十字标记，之后所有平移都从它量。
- `up_true`：门中心相对**光轴高度**的垂直距离（门中心更高 → `up+`）。**不要**用"离地高度"当 `up`。
- `yaw_true`：船体相对"正对姿态"（门居中且左右边等长）的转角。台架用转台刻度；
  水里用 `python3 common/turn_deg.py --deg 20 --dir left`（闭环走遥测 yaw），
  **这次实验里它充当角度参考**；要更严格就用外部角度基准（地面线 + 激光笔）并在备注里写明用了哪种。

**布置原则**：门固定不动（挂墙/挂架），**动船**（移船比移门容易且可复现）；
门面尽量与船的预期航向垂直，避免引入额外 `pitch/roll`。

## 4. 实验步骤（**陆上 / 水下 分开做**）

> ### 为什么两边都要做（2026-09-22 晚更新：平面窗假设已被排除）
>
> 相机前面是**透明半球罩**（不是平面窗）。罩的效应 ∝ 罩外表面的折射本领 `n_罩−n_外`
> （1.49−1.00 = **0.49** 空气 / 1.49−1.33 = **0.16** 水）⇒ **空气与水是两个不同的等效内参**，
> 而且**平面窗那套 `k≈n≈1.33` 不适用**（实测方向还相反：空气视场更窄）。
> 两个未知量仍然互相退化：
>
> ```
> z_meas = z_true · (fx_cfg/fx_med) · (W_cfg/W_true)     ← fx_med 与 W_true 无法只靠"量门"分开
> ```
>
> ⇒ 顺序：**先用物理靶子（已知长度的卷尺刻度）定 `fx_med` → 再用门的 Δu 反解 `W_true`**。
> 靶子法两边各做一次：空气 §A0b、水 §B4。
> ⚠️ **不再有"陆上先定 `W_true`"这条路** —— 岸上的 `fx_air` 也是未知的（≈990~1200），
> 先定 `W_true` 会把 `k_air` 混进门框尺寸里。

| 阶段 | 在哪 | 谁出角点 | 主要回答 | 章节 |
|---|---|---|---|---|
| **A 陆上** | 台架 / 工作间 | **手工标注**（检测器在空气域不响应：实测最高分 0.074） | **空气侧 `fx_air` 与 `c`（靶子法，§A0b）**、`t_x/t_y/psi` 的符号与尺度、位姿可用率 | §4A |
| **B 水下** | 水池 | **检测器**（水下工作）+ 少量手工标注对拍 | **`fx_water` 是否 = 1207.6（靶子法复核，§B4 ★第一优先；旧判据 782.5 已作废）**、水下 PnP 深度、检测器出点质量、响应距离上限、倒影对 `conf_thr` 的影响 | §4B |
| **C 离线** | 任意 | 用 A/B 产出的 dump | 选参扫描、p3p 对比、**回填与复核** | §4C |

两个阶段的产出格式**完全一样**（都是 `preview_detect --dump` / `label_corners` 那种 JSONL），
所以 `tools/analyze/pnp_calib.py` 对两边一视同仁：**只要文件名里带真值，就能一起算、分开算**。

### A0 器材与口径（先定死，否则会拟合出假偏置）

| 量 | 怎么量 | 符号约定 |
|---|---|---|
| `z` | 从**镜头外壳**（在机身侧面用笔标一点）量到**门管中心线所在平面**；尺子贴地拉直 | 恒正 |

>
> ⚠️ **修正（2026-09-22 晚）—— 换零点≠把 `c` 归零**。之前这里写过"把 0 贴到罩顶 `c` 就归零"，**这是错的**：
> `c` 是**光心（入瞳）相对你这个零点向后的距离**，是相机的物理属性；换零点只是**把 `c` 固定成一个常数**，
> 它不会变成 0。（若真实光心在罩顶后方 16 cm，那么"0 贴罩顶"时 `c` 就是 −0.16 m，不是 0。）
> ⇒ 正确做法：**零点固定成制度**（量法可复现），**`c` 用 §A0b 的卷尺靶子法实测一次**，之后一直用这个值。
>
> **为什么非要这个 `c`**：`z_meas = s·(z_tape + c)` 对 `z_tape` 线性 ⇒ `c = 截距/斜率`（见 §5.3b）。
> 2026-09-22 三档干净数据（1.5/2.0/2.5 m）现算得
> `z_meas = 0.7743·z_tape − 0.1235` ⇒ **`c = 截距/斜率 ≈ −0.16 m`**
> （在**本 runbook 统一约定** `Δu = fx·L/(z_tape + c)`、即 `z_true = z_tape + c` 下；
> 旧版 §5.3b 写的 `+0.156` 是另一个符号约定，**已统一为负**），
> 但**这批数据只把 `c` 定到 ±0.03 m（点击噪声）/±0.10 m（若标注有 2% 系统偏差）**，
> 因为 2.5 m 档的比值（0.730）比 1.5/2.0 m 档（0.701/0.699）高 4%
> ⇒ 这条"非线性"会被两参数拟合吸收成一个假 `c`。**只有 §A0b 的物理靶子能把它定死。**
>
> ⚠️ **手持门的限制（2026-09-22 现场条件：没有支架、空间有限）**：手持可以拿到
> **比例 / 符号 / 一致性**这三类结论，但**不能**用来判 `b`（截距/偏置）与 `psi` 的绝对量 ——
> 手持必然带 pitch/roll 与轻微距离抖动。若现场能找到支架、挂钩或靠墙，优先把门固定住；

**做法（约 15 min；一档一条命令，图存到 `ruler_*` 目录，别混进 `pnp_*`）**

```bash
# ① 采图：三档各一条命令（相机/船在每个档位上摆好，别在采图期间改距离）
python3 tools/analyze/label_corners.py --capture log/pnp_$(date +%m%d)/ruler_z150 --n 3   # === 1.50 m ===
python3 tools/analyze/label_corners.py --capture log/pnp_$(date +%m%d)/ruler_z200 --n 3   # === 2.00 m ===
python3 tools/analyze/label_corners.py --capture log/pnp_$(date +%m%d)/ruler_z300 --n 3   # === 3.00 m ===

# ② 量刻度：点 3 个刻度（左/中/右，即 0 / 50 / 100 cm），一个 JSONL 收全部三档
D=log/pnp_$(date +%m%d)
python3 tools/analyze/label_corners.py --measure --images "$D/ruler_z150/*.jpg" --out $D/ruler.jsonl
python3 tools/analyze/label_corners.py --measure --images "$D/ruler_z200/*.jpg" --out $D/ruler.jsonl
python3 tools/analyze/label_corners.py --measure --images "$D/ruler_z300/*.jpg" --out $D/ruler.jsonl

# ③ 解算 (fx, c) + 留一校验 + 与 cfg fx 的比例 k_med
python3 tools/analyze/ruler_calib.py --report $D/ruler_air.md --title "空气侧靶子法" $D/ruler.jsonl
```

1. 🔴 **卷尺要横着放**（2026-09-22 实测教训）。画面是 **1280×720** —— **宽度方向的余量是高度方向的 1.78 倍**。
   竖着贴卷尺，可用高度只有 720 px，于是"1.00 m 跨度"在 1.5 m 处要 ~735 px 就必然出框
   （现场就是这样：只有 3 m 档能完整呈现 0–100）。横过来放（贴墙/横杆/桌沿）就能全部装下：

   | 档 | 水平 1.00 m 跨度需要（fx≈1100） | 装得下？ |
   |---|---|---|
   | 1.00 m | 1100 px | ✓（勉强，两侧各留 90 px） |
   | 1.50 m | 733 px | ✓ |
   | 2.00 m | 550 px | ✓ |
   | 3.00 m | 367 px | ✓ |

   ⚠️ **竖向量的意义不同**：竖向跨度量到的是 **`fy`**（不是 `fx`），而门宽走的是 `fx`。
   两者在 cfg 里只差 0.35%（782.54 vs 779.79；🔴 新 C 是 **1207.64 vs 1208.55 = 0.08%**，更接近等比），但在罩下是否等比**未验证** ⇒
   **要么全部横着量（直接得 `fx`），要么全部竖着量并明确按 fy 解读**，别一档横一档竖。
2. 让卷尺的**一段刻度窗口**（不必包含 0 端！）落在画面**中部**：取三个等距刻度 —— 起点、中点、终点。
   `L` = 起点与终点的刻度读数差（例：20 / 45 / 70 cm → `L = 0.50 m`，用 `--span-m 0.50`）。
3. 从**机身零点标记**（§A0 那个固定点）量到靶面，各档拍一张；**靶面要正对光轴**；
4. 量刻度时点 **3 个点**（工具自动算 `Δu`、前后半跨、`skew`、中点偏离）：

   ```
   Δu = |P₃ − P₁|（**欧氏距离**，横/竖/斜都成立）   skew = (后半 − 前半)/Δu ≈ (L/2)·sinψ / z
   ```

   ⚠️ **`skew` 就是"有没有正对"的当场探针**：1.00 m 跨度 @2 m 时 `skew` 2% ≈ 偏 4.6°，
   而 5° 斜视就能让 `fx` 偏 1~2%（= 我们的目标精度）⇒ **`|skew| > 2%` 就转船重拍**，别硬用。
   工具还会报 `off_mid`（中点离两端连线的垂距，卷尺有折角/点错刻度时变大）。
   2026-09-22 首次实测的 skew 是 **+4.5%**（中点偏 8.5 px ≈ 2.25 cm）⇒ 这一档的跨度仍可用，
   但它告诉我们**单点判读精度约 ±2 cm**，也就是 `fx` 的 ±2%。

**解算（`ruler_calib.py`）—— 两条路，看你有几档**：

```bash
# ① 两档以上：直接解 (f, c)
python3 tools/analyze/ruler_calib.py --report $D/ruler_air.md $D/ruler.jsonl

# ② 只有一档（或想顺带把"模型眼里的门宽 W_eff"一起解出来）：与门框 dump 联立
python3 tools/analyze/ruler_calib.py --gate "$D/A_pnp_z*.jsonl" \
        --report $D/joint_air.md --title "空气侧 联立" $D/ruler.jsonl
```

① 的模型（`L` 可逐档不同，工具按记录里的 `span_m` 处理）：

```
Δu = f · L / (z_tape + c)      c = 光心相对零点的偏置(m)
⇒ f  = (z₁ − z₂) / [ L·(1/Δu₁ − 1/Δu₂) ]      c = f·L/Δu₁ − z₁      （1 = 近档）
```

② 的模型（`fx = ratio·fy`，`ratio` 取 cfg 的 fx/fy）：**单档靶子只有 1 个观测，`(f, c)` 是整条曲线**，
但门框的 3~4 档提供额外的"比例"信息，于是 `(fy, c, W_eff)` 三个未知量能一起压出来 ——
代价是 `c` 与 `W_eff` 强耦合，工具会打出**`c` 的简并剖面表**（那张表就是不确定度）。

预期 `Δu`（1.00 m 跨度，`c` 未定时只是参考）：

| 假设 | z=1.50 m | z=2.00 m | z=3.00 m |
|---|---|---|---|
| 标定对（fx=782.5, c=0） | 522 px | 391 px | 261 px |
| fx=1110, c=0 | 740 px | 555 px | 370 px |
| fx=1010, c=−0.16（A1 拟合的等价位） | 610 px | 468 px | 320 px |

⚠️ **若三点不共线**（第 3 档明显偏离前两档解出的直线）⇒ 说明还有畸变残差或某种
距离相关偏差没被两参数模型容纳，**先别下结论**，把 `--frame-w` 复算与 §4C 的残差图看一眼。

**精度预算（为什么用 3 档、间距拉开）**：

| 测法 | 定什么 | 主要误差源 | 量级 |
|---|---|---|---|
| 画幅边缘量墙面宽度（**2026-09-22 踩过，废**） | 只有 fx | ①距离口径 15~20 cm → **±18%**；②边缘处 raw vs 去畸变差 ~30%（k1=−0.49）；③可见宽目测 ±5 cm → ±4% | fx ≈ 870~1088（同一张图） |
| 卷尺靶子 2.00 & 3.00 m | fx, c | Δu 点击 ±2 px（~0.5%） | fx **±3%**、c **±6 cm** |
| **卷尺靶子 1.50 & 3.00 m（推荐）** | fx, c | 同上 | fx **±2%**、c **±3 cm** |

（`c` 的灵敏度 ∝ 1/(Δu₁−Δu₂)：1.5↔3.0 m 的差值约是 2.0↔3.0 m 的两倍，所以 `c` 精度翻倍。
2.00 m 那档留着当**线性度校验**，不做也不影响解算。）

**废掉墙测的账（2026-09-22 实测）**：

| 可见宽（z_tape=0.85 m） | 推出 fx |
|---|---|
| 1.00 m | 1088 |
| 1.10 m | 989 |
| **1.15 m**（用户报） | **946** |
| **1.20 m**（用户报） | **907** |
| 1.25 m | 870 |

- 边缘目测 ±5 cm → fx ±4%；**距离口径差 15 cm → fx ±18%**（`W=1.15` 时：0.85 m→946、1.00 m→1113）；
- ⇒ 墙测**只判方向**（够说明"实际视场比标定窄"），**数值一律不写进 cfg、也不填进 §6 表 A0b**。
  想留着当快速 sanity check 可以，但只能是"窄了还是宽了"这一个 bit。

**这把 `c` 也定下来了** —— 之后所有"距离真值"都用§A0 那个固定零点 + 这里解出的 `c`，
所以一次把 fx 与 c 都解出来，比只测一个 fx 值值钱得多。

**§A0b + §A1 一起才能回答"四角标在外缘还是中心线"**：A0b 给出 `fx`（纯几何，与门无关），
代回 A1 的 `Δu`：`W_eff = Δu·(z_tape + c)/fx`。
- `W_eff ≈ 0.77` → 角点在外缘，与 cfg 一致；
- `W_eff ≈ 0.72` → 在管子中心线 ⇒ 应把 `frame_w/frame_h` 改成 0.72/0.51；
- `W_eff ≈ 0.67` → 在开口内缘 ⇒ 改成 0.67/0.46。

⚠️ **一条不依赖 `W_eff` 的反证（09-22 干净三档 1.5/2.0/2.5 m）**：门框外缘只有 0.77 m，
所以 `fx_t·W_eff = Δu·(z_tape + c) ≤ fx_t × 0.77`。把 782.5 代入反解 `W_eff`：
三档会给出 **`W_eff ≈ 1.11 m`** —— 比门框外缘还宽 44%，**物理上不可能**
（若把尺度塞进 `c` 也救不回来：`fx=782.5` 要让 1.5 m 档成立需要 `c=−0.45`，2.5 m 档需要 `c=−0.67`，两者不自洽）。
⇒ **`fx` 一定比标定值大**，只是具体大多少取决于 `(c, W_eff)` 怎么分：

| `c` | `fx`（若 `W_eff`=0.77 外缘） | `fx`（若 `W_eff`=0.72 中心线） |
|---|---|---|
| −0.16（A1 拟合值） | 1010 | 1080 |
| 0 | 1094 | 1170 |
| +0.16 | 1185 | 1266 |

（`c` 的物理口径一般不超过 ±0.2 m ⇒ **`fx_t` 落在 ~990–1200**，即 **1.27×~1.53× 标定值**，
`k_a = fx_标定/fx_t ∈ [0.65, 0.79]`。这正是"罩把视场收窄"的定量指纹，§A0b 的靶子法负责把它钉到一个数。）
`c` 的符号约定见 §A0；`c<0` 意味着"有效距离比卷尺读数小"，多数情况下是**3 档噪声被两参数拟合吸收成假 `c`**。

**在定标完成前怎么继续**：比例是常数 ⇒ A1 照样给得出 `R²`、曲线形状与**符号结论**；
但 `a` 的绝对值 = `k_a`（相机比例）× `k_W`（门框口径），两者**简并** ⇒ 必须先用 A0b 钉住 `k_a`。

**推荐架构（不要靠 `frame_w` 吸收比例）—— 2026-09-22 已确认这是必须的**：`vision.camera.front.calibration`
是**唯一入口**（`board_camera()` / gate 与 ball 两个预处理都在读它）⇒ 两份标定文件，按当次实验切换这一个键：

### A3b 斜门能过吗？（2026-09-22 用合成数据回答，**不用占现场时间**）

**问题**：门要是斜着摆（绕竖轴大角度），psi 还准不准？—— 因为这决定"能不能过较斜的门"。

**合成扫描**（门框 0.77 m、z=1.5 m、角点噪声 σ=1.2 px，内参用空气侧 1078）：

| 真值斜角 | psi 误差中位 | 帧间 std | 4 角解算成功率 |
|---|---|---|---|
| 0° | −0.10° | 0.68° | 200/200 |
| 20° | +0.05° | 0.42° | 200/200 |
| 40° | +0.01° | 0.24° | 200/200 |
| **70°** | **−0.01°** | **0.14°** | 200/200 |

⇒ **越斜越准**（透视越强、平面位姿条件越好），σ=2.5 px 时误差仍 ≤0.13°。
**psi 对内参误差宽容**：故意用错 30%（水下 782.5 vs 空气 1078）时，psi 误差 ≤ **3.5°**（20~30° 处最大）
⇒ 即使"水下 fx 未验证"这件事有 30% 的偏差，航向控制也不会崩（但 RMS 会涨到 5~14 px，那是"内参不对"的信号）。

**两条与斜面有关的代码事实**（读过代码，非推测）：

| 事实 | 依据 | 含义 |
|---|---|---|
| THROUGH 只能由 `full` / `p3p` 触发（`z ≤ z.cross`） | `gate_task.py:550` 在 `_on_pose` 里 | `width`/`coarse` 档**没有**米制穿门判据（出口只有 near-lost / loiter）⇒ 斜门下丢角点不会"按错距离冲门" |
| **p3p 的 psi 在 10~20° 斜角下不可信**（合成：10° 时误差 +14.5°、std 7.5°；0° 与 ≥30° 反而好） | 合成扫描 + `heading_align.py` 只吃 `mode == full` 的 psi | 设计正确：**航向只用 full 的 psi**（`gate_task.py:534` 那个 `if mode == MODE_FULL`） |
| `_on_width` 的 `z = fx·W/Δu` **不含旋转** ⇒ 斜门下 Δu 缩小 `cos(psi)`，z 读大 `1/cos(psi)` | `gate_task.py:646`、docstring"只判该不该靠近" | 45° 斜门时 `width.z_max=1.5` 实际对应 **1.06 m**（更靠近）⇒ 斜门尽量靠 `full` 档走；靠 width 兜底时要有心理准备 |

**角点误差 → psi 误差**（合成，z=1.5 m，full 4 角；"5 帧中位数"就是 `hdg.measure_frames=5` 实际用的量）：

| 角点噪声 | 逐帧 psi std（0°斜角） | 逐帧 std（45°） | **5 帧中位数误差** | 5 帧 std |
|---|---|---|---|---|
| 独立 σ=2 px | 1.16° | 0.36° | ≤0.47° | ≤0.63° |
| **独立 σ=5 px** | 2.82° | 0.86° | **≤1.04°** | ≤1.47° |
| **系统性 +5 px**（四角同向平移） | — | — | **≤0.25°** | 0 |
| **系统性外扩 5 px**（框放大/缩小） | — | — | **≤0.22°** | 0（但 z 读 1.478，−1.5%） |

⇒ **psi 对角点误差极其鲁棒**：5 px 的独立噪声只让 5 帧中位数偏 ≤1°，**系统性偏差几乎完全不影响 psi**
（整体平移被位姿吸收，整体缩放只改深度）。相比之下同一个 5 px 外扩就能让 **z 差 1.5%**、`reproj_px` 涨很多。
**校验 psi 时别拿 z/RMS 当替身**——它们对误差敏感得多。

**HDG 的触发条件**（`gate_task.py` 逐条读出，2026-09-22）：

进入正航向需要**同时**满足 4 条：

| # | 条件 | 代码位置 / 参数 |
|---|---|---|
| 1 | `comm.gate.hdg.enable: true`，且**本门还没做过**正航向 | `gate_task.py:164/197`，`_hdg_done` |
| 2 | 相位 = ALIGN 且子状态 = **GOLDEN**（不是 CREEP/HOLD/REACQUIRE） | `gate_task.py:577` 起 |
| 3 | **居中连续达标 `align.confirm_frames`（=4）帧**：`\|dxn\| ≤ px_x(0.20)` 且 `\|dyn\| ≤ px_y(0.25)` | `gate_task.py:591-594` |
| 4 | **本帧是 `full` 且 psi 新鲜**（`now_ms − _hdg_ms ≤ fresh_ms=800ms`） | `_hdg_fresh/_hdg_ready`，`gate_task.py:248-262` |

🔴 **第 4 条的真实含义（2026-09-22 读代码 + 用例确认）**：`fresh_ms=800` **是空转的** ——
**每个 full 帧都会刷新 psi 的时间戳**（`gate_task.py:534` 那个 `if mode == MODE_FULL`）
⇒ "psi 新鲜"真正等价于 **"当前这一帧是 full"**。而且 `_on_width` 的 ALIGN 分支**从不启动 HDG**。
⇒ **卡住正航向的不是 800 ms，而是"居中达标那一刻必须正好是 full 帧"**（远距/斜门只在部分帧出 4 角时就中招）。
日志里新增字段 **`hdg_skip`** 记录原因（`mode=p3p(...)` / `off` / `done` / `no_psi` / `stale`），
`tools/analyze/analyze_task_log.py` 的 ⑦b 段会把它汇总打印。

新增开关 **`comm.gate.hdg.wait_fresh_ms`（默认 0 = 旧行为）**：>0 时若那一刻不是 full，
船**原地等**（动作 `wait_hdg`，不下发 surge）最多这么久，等到 full 就进正航向，超时才进 APPROACH。
斜门/远距建议 **1500~2000**。代价只是时间（GOLDEN 本来就不前进）。

第 3 条满足而第 4 条不满足 → **不进正航向，直接转 APPROACH**（带着残余航向走）。
⚠️ 而且 `_on_pose` 路径**没有回到 ALIGN 的路**（只有"角全丢 → coarse"那条会退回 ALIGN）
⇒ 一旦跳过，**这一趟就不会再正航向**（斜门 + 残余航向正是最危险的组合）。
⚠️ **对斜门这正是风险点**：越斜越容易丢角点/拿不到 full ⇒ 越容易跳过正航向。
HDG 期间 `sway/heave/surge` 全 0（只转，测量要求静止），转完回 GOLDEN **复核居中**。
每门的内部流程：SETTLE(400ms) → MEASURE(攒 5 帧 full 取中位) → `|psi| ≤ tol_deg(8°)` 就锁定 DONE
→ 否则按**冻结的**目标角转（`max_iters=3`，超时 8s）→ 再测；迭代用完 GIVEUP（带残余航向继续走）。

**转向的极性不是假设**：`TurnCore` 在首次转向时用 0.6s/0.3 舵量**探向**（`common/turn_deg.py:20`），
用下位机回传的绝对航向闭环；**没有遥测就拒转**（等待 `wait_tel_ms=3000` 后放弃正航向）。
所以"推进器极性"这一条已经被设计消掉了 —— 前提是**遥测 yaw 是通的**。

**航向执行的余量**：`hdg` 单次转向不设上限（`max_step_deg=0`）、超时 8 s。
45° 在 10~20°/s 下需 2.2~4.5 s ✓ 够；`max_iters=3` 对"测→转→停稳→再测"足够。
⇒ **限制斜门的不是 psi，而是检测器在近侧边缘-远侧边缘压缩下的出点质量**（水里 §B2/B3 才能量）。

# §4B 水下（水池）测量 —— 检测器路线

> 目标：① 量检测器的**响应距离上限**；② 用检测器出点量**水下 PnP 深度**并与卷尺比；
> ③ 定**折射因子 k / 有效内参**；④ 看倒影/光照对 `conf_thr` 的影响。
> 预算 ~40 min（其中 B1 10 min、B2 15 min、B3/B4 10 min、B5 5 min）。

### B0 下水前的硬性条件

| 项 | 要求 | 为什么 |
|---|---|---|
| **水线** | 相机窗口与**整扇门**都要在水面以下；水线不许切过镜头或门 | 水面是第二个折射面+反光面，几何会乱掉，量出来的 k 不干净 |
| 镜头 | 下潜前镜头**干净干燥**；入水后等 1~2 min 让机壳温度平衡再采 | 起雾会让角点整片糊掉（现象像"模型不行"） |
| 姿态 | 船保持**水平、正对门**，`roll/pitch` 尽量小 | 减少额外分量 |
| 遥测 | 画面叠加里 `depth=…` 在跳（不是 `n/a`）；`min=0.55m` | 限深保护有效；顺便确认下位机在上行 |
| 距离 | 用**卷尺/标尺杆**量门管中心平面到镜头外壳 | 水下读数要在同一口径下量（可在岸上标好杆长） |

**角度真值怎么摆准**（2026-09-22 教训：名义 ±20° 实际可能偏差 6°，会把 psi 的好坏完全掩盖）：
用**门框自身的宽度当量角器** —— 门宽 `W` 绕中心转 `θ` 时，两立柱沿**深度方向**的相对位移 =
`W·sinθ`（0.77 m、θ=30° ⇒ 0.385 m；θ=45° ⇒ 0.545 m）。在地面量出这个位移打两个点，
把两立柱分别对准 ⇒ 角度精度 ≈ `atan(1 cm/0.4 m) ≈ 1.4°`，比目测好一个量级。
判据：`psi` 与真值之差的**中位数 ≤ 3°**、帧内 `std ≤ 4°`，且 0/±15/±30/±45 单调、**无符号翻转**。

判据：符号与陆上一致；`|t_x − lat|`、`psi − yaw` 的偏差**量与陆上同量级**（若水下明显放大 → 折射非线性，需要分档建模）。

### B4 水下等效内参验证 ★★★（**本 runbook 里最该先做的一条**）

**为什么它是第一优先**：`front_camera.yaml` 是水下标定出来的 ⇒ **水里就是它该用的地方**，
而 `z.cross=0.77`、`z.near_lost_m`、`depth_guard.min_depth_m`、`align.px_*` 全都在吃这份内参。
岸上的 0.70 比例**不能**用来判它（那是介质差）；**只能在水里用物理靶子判**。

```
k = (水下 z_meas / z_true) / (空气侧 z_meas / z_true)
```

- **做法（与 §A0b 同一套靶子、同一条命令，10 min）**：卷尺刻度贴在一根直杆/浮板/池壁上，
  让 **0 / 50 / 100 cm** 三个刻度落在画面中部；靶面放在 **1.00 / 1.50 / 2.00 m**（水里更浊，档位比岸上近）。

  ```bash
  D=log/pnp_$(date +%m%d)
  python3 tools/analyze/label_corners.py --capture $D/wet_z100 --n 3     # === 1.00 m ===
  python3 tools/analyze/label_corners.py --capture $D/wet_z150 --n 3     # === 1.50 m ===
  python3 tools/analyze/label_corners.py --capture $D/wet_z200 --n 3     # === 2.00 m ===
  python3 tools/analyze/label_corners.py --measure --images "$D/wet_z100/*.jpg" --out $D/ruler.jsonl
  python3 tools/analyze/label_corners.py --measure --images "$D/wet_z150/*.jpg" --out $D/ruler.jsonl
  python3 tools/analyze/label_corners.py --measure --images "$D/wet_z200/*.jpg" --out $D/ruler.jsonl
  python3 tools/analyze/ruler_calib.py --report $D/ruler_wet.md --title "水下靶子法" $D/ruler.jsonl
  ```

  ⚠️ **相机—靶距离必须在**水里**量**（标好刻度的长杆，别靠岸上刻的记忆）；
  ⚠️ 靶面同样要正对光轴 —— 水里的 `skew` 判据不变（`|skew| > 2%` 就重摆）。
  ⚠️ 若水里检测器可用，也可用 `preview_detect.py --gate-kpt --save` 抓帧对拍，但**靶子法才是判据**。
- **判据（验收）**：
  | 结果 | 结论 | 动作 |
  |---|---|---|
  | `fx_water = 782.5 ± 5%` | 水下标定仍有效，`front_camera.yaml` 就是跑船要用的 | **不动任何 cfg**；只把 `c` 记进 §6 表 A0b |
  | 偏差 5~10% | 罩/镜头有轻微变化 | 记进表 A0b，考虑在水里重标 |
  | 偏差 > 10% | 标定过期或装罩状态变了 | 在**水里**重标（棋盘格）→ 新 yaml → 重跑响应阶梯 |
- `k` 的期望值：罩效应 ∝ 罩外折射本领 ⇒ 空气侧被收窄得更多、水里更接近裸镜头
  ⇒ **预期 `k = fx_air/fx_water > 1`（约 1.3~1.5）**。若测出来 `k < 1`（水里视场更窄），
  说明我这条模型错了 ⇒ **以实测为准**，并且要重新审视"岸上 0.70 是介质差"这个解释。
- 若 `k ≈ 1` → 罩的入瞳设计良好（球心≈入瞳），水陆一致，一份标定走天下。
- ⚠️ **不要预设 `k≈1.33`**：那是**平面窗**的数，半球罩不适用。
- 复算表达：`pnp_calib --frame-w <候选值> --no-invert <dump>` 可以离线看"换成这个标尺后误差是多少"。

#### ⑤ 结论 3：水陆两个有效焦距都测到了 ⇒ **k ≈ 1.12**

- 空气侧：靶子法/刻度法 `fx_air ≈ 1075~1111`（§A0b），本工程用的那份取 **1078**；

### 5.3 门框尺寸反演（工具已实现；`--no-invert` 可关）

> ⚠️ **前置条件（2026-09-22 晚追加）**：本节只在**你已经用靶子法确定了该介质的 `fx_med`** 之后才成立。

### 5.3b 从 A1 的拟合里**免费**拿到距离口径偏置 `c`

因为 `z_meas = s·(z_tape − c)` 对 `z_tape` 是**线性**的（`s` = 斜率、截距 = `−s·c`），
所以**A1 的线性拟合本身就同时给出比例与口径偏置**：

```
c = −(截距) / (斜率)
2026-09-22 实测（三档干净数据 1.5/2.0/2.5 m）：`z_meas = 0.7743·z_tape − 0.1235`
⇒ `s = 0.7743`、**`c = 截距/斜率 ≈ −0.16 m`**（符号约定统一见 §A0：`z_true = z_tape + c`）
⇒ `fx_t·W_eff = fx_cfg·W_cfg / s = 602.5/0.7743 ≈ 778 px·m`
```

⚠️ **`c` 不是"把卷尺零点挪一下就能归零"的东西**（旧版这里写错了，2026-09-22 晚修正）：
`c` = 光心相对你零点标记的偏置，是相机的物理属性；换零点只把它变成另一个固定常数。
**能做的是"零点制度固定 + `c` 用 §A0b 靶子法实测一次"**。

⚠️ 而且**只用 A1 的三档解不干净 `(K, c)`**：这批数据里 2.5 m 档比值 0.730 比 1.5/2.0 m 档
（0.701/0.699）高 4%，两参数拟合把这 4% 吸收成 `c=−0.16`；蒙特卡洛显示
标注有 2% 系统偏差时 `c` 的不确定度就有 **±0.10 m**（点击噪声 ±2 px 时 ±0.03 m）。
⇒ `c` 的**绝对值**必须靠靶子法，A1 只能给"比例 `s` 与曲线形状"。

## 7. 常见故障与排除

| 现象 | 最可能原因 | 处置 |
|---|---|---|
| 全场 `可用率=0`、`mode=coarse` | 权重没跑起来 / 忘了 `--gate-kpt` | 先做 S0；看终端有没有 `det` |
| 只有近距档 `可用率=0`、RMS 却很大 | **`frame_w/frame_h` 比例不对**（残差超 `reproj_px`） | 临时 `--reproj-px 40` 复算确认，再按 §5.3 反演 |
| 各档误差**随距离单调漂** | 真值口径不一致 / 畸变残差 / 角点系统性外扩 | 统一零点；跑 `tools/analyze/analyze_kpt_dump.py` 看角点口径 |
| `z_meas` 比卷尺**小**（`a<1`） | `frame_w` 标小了 | 按 §5.4 乘 `1/a`（**不要**手写"补偿系数"） |
| `t_x` 符号反 | 相机域/坐标约定搞错 | 查 `image.undistort` 与 `dof_map`，**不要在任务里加负号** |
| `psi` 每档偏置都不一样 | 转台/地面角度线没校准 | 重做 S4；先确认"正对"姿态真的正对（`dxn≈0` 且左右边等长） |
| 某些 dump 解析不出真值 | 文件名缺 `z<厘米>` | 重命名，或用 `--gt gt.csv` |
| 岸上 `preview_detect --gate-kpt` 一直 `det=0` | **空气域不匹配**（实测最高分 0.074；同权重水下 0.94） | 岸上改用 §4A 手工标注；检测器的事留到水下 §4B |
| 各档 `z_meas/z_true` 稳定偏一个常数（如 **0.70**） | **半球罩的等效内参随罩外介质变**：岸上（空气）实测 fx_eff≈1110，而 782.5 是**水下标定值** ⇒ 岸上偏小 ~30% 是预期的；**水里是否也偏，只有水下靶子法能回答** | ①先做 §4B-B4（水下靶子法）判 782.5 还准不准；②岸上调参另建 `front_camera_air.yaml`，按介质切换 `camera.front.calibration` |
| 横向 ±50 cm 有角点出画面（**岸上**） | 岸上视场比水下标定值窄（空气里罩的功率强 3 倍） | 岸上删掉该档；**水下这一档要单独试**（水里视场更宽，可能装得下） |
| 水下各档深度都偏同一个比例（≈25%） | 平面窗折射（`k≈1.33`） | 按 §4B-B4 算 k 并决定回填哪套标尺 |
| 水下只有近距能出角点 | 检测器响应距离上限（见 B1） | 中段参数（`slow_max`/`width.z_max`）只能用该距离内的数据，或先解决远距检测 |
| 帧率异常低（<5 fps） | 推流开着 / 分辨率或模型没对上 | 关 `stream.enable`；看启动横幅的权重与输入尺寸 |

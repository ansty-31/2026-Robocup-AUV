# 靶子法现场卡（空气 §A0b / 水下 §B4 通用）

> 目的：用**长度已知**的卷尺刻度当靶子，把两个数解出来 ——
> **等效焦距 `fx`（水平靶线）/ `fy`（竖直靶线）** 与 **距离口径偏置 `c`**。
> 它们是把"相机/介质比例"和"门框口径"分开的**唯一**手段（只看门框时两者简并）。
> 完整背景见 `doc/实验待测-runbook.md` §A0b / §B4。

---

## 一、摆位（三条铁律）

1. **零点固定成制度**：卷尺 0 端用胶带固定在机身/罩顶的**同一个记号**上，每次都用它。
   ⚠️ `c` 是**光心相对这个零点的距离**（相机物理属性）——换零点只会把它变成另一个常数，
   **不会归零**。`c` 由解算给出，不用你事先消掉。
2. **靶面正对光轴**（靶面 ⟂ 光轴）。
3. **靶线尽量水平**：画面 1280×720，**宽度余量是高度的 1.78 倍**；
   竖着贴卷尺只有 720 px 可用（1.00 m 跨度在 1.5 m 处要 ~735 px 就出框）。
   水平方向即使只有 50 cm 可用也完全够。

## 二、取刻度窗口（不必包含 0 端！）

选**三个等距刻度**：起点 / 中点 / 终点。`L` = 起点与终点的刻度读数差。

| 例子 | `L` | 传给工具 |
|---|---|---|
| 0 → 50 → 100 cm | 1.00 m | `--span-m 1.0`（默认） |
| 20 → 45 → 70 cm | 0.50 m | `--span-m 0.5` |
| 10 → 30 → 50 cm | 0.40 m | `--span-m 0.4` |

中点必须点**真正的中间刻度**（工具的 `skew` 就是靠它算的）。

## 三、档位怎么选（**由蒙特卡洛定，别凭感觉**）

`L = 0.50 m`、点击 σ=1.5 px、距离 σ=1 cm 时的精度：

| 档位组合 | `fx` 精度 | `c` 精度 |
|---|---|---|
| 1.5 & 2.0 m | ±3.6% | ±5.8 cm | ← 近档组合，**不达标** |
| **1.5 & 3.0 m** | **±1.8%** | **±3.3 cm** | ← 可达时的首选 |
| **1.0 & 3.0 m** | **±1.4%** | **±1.9 cm** | ← 最好 |
| 1.0 & 1.5 & 2.0 & 3.0 m | ±1.4% | ±2.0 cm | ← 最稳 |

> `c` 的精度只由**距离跨度**决定（与 `L` 大小无关）；`L` 越小，同样的点击误差占比越大。
> 判据：`fx` ±2%、`c` ±3 cm ⇒ **至少要让最远与最近档相差 2 倍以上**。

## 三-b、**更稳的做法：不点鼠标，量刻度周期**（★推荐先试这个）

卷尺每 1 cm 就有一条刻度线 ⇒ 一条尺上有几十条，「1 cm = 多少像素」是一个**周期估计**问题：
精度 ~0.5%、完全不用点，而且**没有点错刻度的风险**（这正是 2026-09-22 丢了一整档数据的教训）。

```bash
python3 tools/analyze/tape_ticks.py --z 1.00 log/pnp_0922/ruler_z100/*.jpg
# 不确定自动检测对不对时，显式给行带与横向范围（打印出来的带/范围要自己核一眼）
python3 tools/analyze/tape_ticks.py --z 1.00 --band 120,140 --x 220,950 \
        --out log/pnp_0922/ruler_ticks.jsonl log/pnp_0922/ruler_z100/*.jpg
```

- 输出里的 `周期` 是**光轴处**的局部比例（= 量的距离正是到尺中心）；
- 工具会同时算一个全局 FFT 周期做**交叉校验**：两者差 >20% 就**拒绝报数**
  （实测 3 m 档：刻度只有 3.6 px、与 JPEG 8×8 块效应同量级，拟合会锁到杂线并自信地
  给出 f=4252 px ⇒ 宁可不报）；
- **只在 1.0~2.0 m 好用**。3 m 处刻度周期 ≈3.6 px 已经接近成像极限，用点击法。

## 四、命令（板端，一档一条）

```bash
cd ~/Desktop/AUV_New
D=log/pnp_$(date +%m%d)

# ① 采图（目录名 = 实际卷尺读数，cm 级；如读到 1.47 m 就叫 ruler_z147）
python3 tools/analyze/label_corners.py --capture $D/ruler_z150 --n 3   # 1.50 m
python3 tools/analyze/label_corners.py --capture $D/ruler_z300 --n 3   # 3.00 m

# ② 量刻度：点 起点 / 中点 / 终点 三个刻度（屏幕提示英文，中文在控制台）
#    --ticks 写上你点的三个读数（cm）⇒ 工具自己算 span，避免手填错
#    点完会立刻打印 Δu / skew / off_mid —— |skew|>2% 就重拍
python3 tools/analyze/label_corners.py --measure --ticks 0,25,50 \
        --images "$D/ruler_z150/*.jpg" --out $D/ruler.jsonl
python3 tools/analyze/label_corners.py --measure --ticks 0,25,50 \
        --images "$D/ruler_z300/*.jpg" --out $D/ruler.jsonl

# ③ 解算
python3 tools/analyze/ruler_calib.py --report $D/ruler_air.md --title "空气侧 靶子法" $D/ruler.jsonl
```

## 五、当场判读（三个数字）

| 看什么 | 判据 | 不达标怎么办 |
|---|---|---|
| `skew` | `\|skew\| ≤ 2%` | 靶面没正对 → 转船/转靶重拍 |
| `off_mid` | ≤ 3 px | 中点没点在两端连线上 → 卷尺有折角/点错刻度 |
| 报告的 `rms` | ≤ 1%（相对） | 档位分布不够开，或标注有系统偏差 |

解算结果怎么用：

- **`fx` / `fy`**：与 `cfg/front_camera.yaml` 的 `fx=782.5 / fy=779.8` 比
  ⇒ `k = f_cfg / f_meas` 就是 **PnP 深度在该介质里的系统性比例**（空气侧实测 ≈ 0.705）；
- **`c`**：之后所有卷尺读数都按 `z_true = z_tape + c` 换算；
- **水平档与竖直档混着量**：工具会**分别解出 `fx` 与 `fy`** ⇒ 顺便验证"罩是否各向异性"
  （不再需要"两轴等比"这个假设）；
- **`W_eff`**（只有联立才给）：模型眼里的门宽。卷尺量的外缘是 0.77，实测偏**管子中线 0.72** 一侧
  ⚠️ 这是**手标**口径；**检测器**的四角标在哪，只能在水里用 §B2 判。

## 五-b、**每个距离档必须用不同的目录名**（血的教训）

采图目录里的文件名永远叫 `cap_001.jpg`… ⇒ `--resume` 与"重测替换旧行"如果按**文件名**去重，
**不同距离档之间会互相覆盖**：2026-09-22 实测把 `ruler_z100` 的整档记录被 `ruler_z300` 删掉
（用 `--resume` 时更会直接跳过整档）。现已改成**按完整路径去重**（记录里写 `src_path`）。
老记录（没有 `src_path`）只能按文件名认，所以：
**升级后第一次用同一个 `--out` 文件时，先把它挪开或备份**（工具也不会主动删它们）。

## 六、已知偏差（写在结论里，别当没有）

- `image.undistort: true` 用的 `D`（`k1=−0.49`）是**水下标定**的 ⇒ 岸上做去畸变其实**过校正**；
  靶子取**画面中部**可把这个影响压到最小，但**残留系统性 ~1~3%（未量化）**。
  这正是"1 cm 刻度法（f≈1083）"与"门框法（假设外缘 0.77 ⇒ f≈1112）"之间那 3% 的主要嫌疑。
- 竖向档量到的是 `fy`，门宽走的是 `fx`；cfg 里两者差 0.35%，罩下是否等比**未验证** ⇒
  **要么全横、要么全竖**，混着量时以工具分轴解出的结果为准。
- 点击精度 ±1.5~2 px 是这套方法的精度地板；放大镜（`+/-`）必须用。

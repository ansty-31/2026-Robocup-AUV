## 3. 代码改动清单

### 3.1 🆕 `gate/gate_postproc.py`（规范 §4 的落地）

纯函数、不碰串口/相机/状态；四条规则各自有开关，缺配置不崩：

| 规则 | 函数 | 要点 |
|---|---|---|
| 可信角点 | `trusted_mask / n_trusted / v_min` | `v ≥ V_MIN`；无角点信息的实例 → 0 个可信（不炸） |
| 几何合法 | `quad_legal` | 四角**顺序合法**（`TL.x<TR.x`、`BL.x<BR.x`、`TL.y<BL.y`、`TR.y<BR.y`）+ **不自交**；只对"恰好 4 个可信角点"的实例判（**门框不全 → 降级，不是丢帧**） |
| 去重 | `dedup / _edge_hits` | 小框 **conf 更低** 且 **≥ min_edges 条边重合**（容差 = `edge_tol × 小框短边`）→ 丢小框。**判据不是包含关系**（规范实测：用包含会误删"落在近门框内的远处真门" 15 个） |
| 统一入口 | `apply` | 几何过滤 + 去重，保序、不改动传入对象 |
| 选门键 | `near_key / corner_key / pick` | `near` = 框宽当测距代理（大 = 近）；`corner` = 09-18 旧行为 |

### 3.2 `gate/gate_decode.py`（接线点）

- 后处理参数 `self._post` 读一次（`gate_postproc.postproc_cfg`）；
- `detect()`（`:208-234`）把 `conf=self._det_conf` 传给 `decode_yolo11_kpt`，再
  `postproc_apply(dets, conf_thr=None, cfg=self._post)` —— **任务与预览看到的是同一批实例**；
  可信口径用 **V_MIN（`keypoint.conf_thr`）**，不是解码期的 `vis_thr`。

### 3.3 `gate/gate_task.py`（选门 + 兜底同步）

  `corner` = 旧行为（角点优先，防"水面倒影形成的第二个门框"抢门）；
- `_D_KPT.conf_thr` `0.9 → 0.8`（与 cfg 同值，用例 `test_gate_defaults_match_cfg` 守）；


### 3.4 `gate/gate_detector.py` / `preview_detect.py`

`build_gate_backend(conf=None, vis_thr=None)` 透传；`preview_detect.py --conf` 现在**同时**覆盖

### 3.5 用例（🆕 `tests/tasks/test_gate_postproc.py`，23 例）

可信角点 / 几何（含蝴蝶结自交、顺序颠倒、非四角不受管）/ 去重（同门两尺度要删、

## 8. 第二轮：冲刺航向闸门 + 居中/近距判据收紧（2026-09-26 晚，用户定）

**动因（板端 `log/gate_one_2026092.jsonl`，19.2 s / 171 帧，过一门）**

```
f=140 15.8s ALIGN GOLDEN center p3p dx=-0.087 dy=0.444 z=0.949 ratio=0.495 hdg=+30.6
f=145 16.4s ALIGN GOLDEN center p3p dx=-0.117 dy=0.416 z=0.868 ratio=0.498 hdg=+30.6
f=146 16.5s THROUGH              p3p z=0.868 ratio=0.498 su=0.6      ← 直接冲
```

三个事实：① 整趟 `hdg_state` 只有 `idle`（139 帧）—— **HDG 从没启动**；
② 冲刺来自**出口②**（近距丢门），判据 `near_lost_m=1.0` ⇒ z=0.868 就判「已过门」；
③ 冲刺时 **psi=+30.6°、dy=0.416**。
根因：新模型下 `mode` 每帧在 full/coarse/p3p/width 间跳（47/78/35/11），`_step` 的「换档清
`_center_cnt`」让居中**永远确认不了** ⇒ 09-23 的「先居中再转 yaw」成了死锁（**航向歪 → 门偏一侧 →
居中不达标 → 不许转 yaw**）。

**改了什么**

| 键 | 旧 → 新 | 作用 |
|---|---|---|
| `gate.z.near_lost_m` | 1.0 → **0.6** | 缩短出口②的距离门（用户："近距丢门的阈值也跟着缩小"） |
| `gate.z.near_lost_ratio` | 0.60 → **0.75** | 出口②的占比判据收紧（同时是出口③ loiter 的"在门口"定义） |
| `gate.through.require_align_deg` 🆕 | **8.0** | **冲刺前的航向闸门**：最近一次 psi > 8° 就拦下（写 `through_block`），不切 THROUGH。三个出口都过闸 |
| `gate.align.confirm_frames` | 4 → **2** | 水下水波复杂、画面难稳（用户："居中稳定 2 帧就转"） |
| `hdg.entry_stale_ok` | false → **true** | 本帧非 full 也能起转（用历史 psi） |
| `hdg.hist_ms` 🆕 | **5000** | 历史 psi 保鲜期；**0 = 不限年龄**；**<0 = 关闭回退** |
| `hdg.entry_psi_first` 🆕 | **true** | **航向优先**：居中没达标也先起转，解上面的死锁；false = 回到旧顺序 |
| `hdg.psi_first_z_max` / `psi_first_ratio` 🆕 | **2.5 / 0.30** | 航向优先的距离门（新鲜 z ≤ 它 **或** 占比 ≥ 它） |

**两个关键实现细节（都踩过坑）**

1. **历史 psi 只用在两个地方**：① 起转判定；② MEASURE 攒不够 full 样本时的**兜底**（`psi_stale` 参数，
   一次）。**绝不能**把历史值当重复样本塞进 MEASURE —— 那会把中位数拉偏、按旧偏差多转一次
   （实测残余 **-13.5°** 的反向超调）。所以 `_hdg_fresh()` 恢复严格语义（只认当帧 full）。
2. **转向中仍然绕开视觉**（`_hdg.turning` 时 `psi_deg=None/sample=False`）；但 HDG 现在允许从任意档位
   进入，所以 **settle/measure 期间遇到 coarse/width 帧**由 `_tick_hdg_degraded()` 接管，
   免得 CREEP/HOLD 把子状态冲掉。

**验证**

- 本地 `pytest tests/ -q` → **191 passed**（含"p3p 不喂滤波器"、"HDG 不被档位退化打断"、"转向后收敛"等既有回归）；
- **脚本化复现**（psi 恒 +30° + 近距丢门，模拟 mode 抖动）：`hdg_entry=psi_first` ⇒ HDG 真的启动；
  冲刺被拦 **217 帧**、**整趟没进 THROUGH**（旧代码会在同一条件下满速冲出去）；
- 板端尚未复测（下一趟下水看 `hdg_entry` / `through_block` / `hdg_susp` 三个新字段）。

> ⚠️ **仍未验证**：这些值没在水里跑过；若发现"迟迟不进 THROUGH"，先看日志 `through_block` ——
> 若一直卡在 `hdg=±xx>8`，说明航向压根修不过来（那是转向/遥测的问题，不是闸门太严），
> 可临时把 `through.require_align_deg` 调到 12~15 或置 0 关闸。

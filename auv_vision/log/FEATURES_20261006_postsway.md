## 1.2 绑定

`align(0.15/0.20)`、`coarse(0.33/0.29)`、`through(0.20/0.25)`、`loiter(0.25/0.30)` —— **四条判据全部是 `(|dx|≤A) AND (|dy|≤B)`，没有任何单轴判据**。两根轴在任何时刻都必须同时通过。

## 1.3 配合程度

| 档 | `corr(dx,dy)` | \|dx\|/\|dy\| | 瓶颈轴（阈值 0.15/0.20） | P(且) vs 独立预期 |
|---|---|---|---|---|
| full | **+0.01**（独立） | **1.80** | `dx`（P 0.68 < 0.85） | 0.54 vs 0.58 |
| width | **+0.71**（强耦合） | **0.33** | `dy`（P 0.76 < 0.97） | 0.74 vs 0.74 |

| 全 | +0.213 | 0.68 | `dx` | 0.36 vs 0.41 |

三条读出来的事实：

1. **主导轴逐档翻转**（full 靠 `dx`、width 靠 `dy`、coarse 两者相当），而四处判据用的是同一对常数。
2. **两轴相关性逐档变化 70 倍**（+0.01 → +0.71）。
3. coarse 档 P(且)=0.09 远低于独立预期 0.22 ⇒ 两轴在阈值附近**互相排斥**，不是独立叠加。

**外因污染不对称**（有测量 full 帧）：`corr(tdep,dx)=−0.76`、`corr(hdg,dx)=−0.46`、`corr(trol,dx)=−0.40`；而 `corr(tpit,dy)=+0.02`、`corr(trol,dy)=−0.07` ⇒ **一根轴被深度/航向/横滚三种外因同时污染，另一根轴基本干净**。

| 深度 | 遥测 `tdep` 全程只动 **0.15 m**，只有 16 个台阶 |

## 5.2 运动规范（由数据定）

1. **`surge` 全部加死区补偿。** `surge=0.30` 只换来 7.9 cm/s，其中 0.138 是执行器死区（`cfg/comm.yaml` 自注值）⇒ 有效推力仅 0.162。补偿后：`creep 0.20→0.34`、`slow 0.15→0.29`、`fast 0.30→0.44`、`through 0.60→0.74`。
2. **`surge` 占空比从 28% 提到 ≥90%。** 现在 58% 的帧 `surge=0`，这是净前进只有 3.9 cm/s 的直接原因。
3. **横向改"定量脉冲"。** 需修正横向行程中位 0.12 m、p90 0.31 m；实测 0.55 对应 7–13 cm/s ⇒ `sway=±0.55` 保持 `T = |X|/0.10` 秒（0.12 m → 1.2 s）。理由是 0 与 0.409 之间空白，逐帧判定只能得到"满档/零"两态。
4. **横向死区从 0.05 提到 0.15**（`|dxa| ≤ 0.10` 的帧占 20%，正是"噪声级偏差"那一段）。
5. **垂向先定零点。** `Y` 中位 −0.126 m、`heave` 单向 94% ⇒ 目标点应设在 −0.13 ~ −0.30 m（或按档分别标），否则垂向回路永久在补偿一个固定偏置。
6. **横向速率的极性无法定**：同样 `sway=+0.55`，一段 dX/dt = −0.070 m/s、另一段 +0.081 m/s；原因是 `corr(dx, hdg) = −0.47`，误差里混着航向。

# 附：修「sway 一直顶在 ±0.55」（2026-10-07，commit 见下）

## 病根（全部由本日志定量）

| 项 | 数 |
|---|---|
| `pid_sway` | `kp=8.0, kd=0.05, out_max=0.55, deadzone=0.05` |
| 比例区宽度 | `out_max/kp − deadzone` = **0.069 → 0.050 = 0.019**，占满幅 **1.9%** |
| PID 的真实误差 | 日志里的**原始 `dx`**（画面中心基准，不是折到主点后的 dxa） |
| 误差尺度 | 有测量 236 帧：`\|dx\|` 中位 **0.090**、p25 0.047、p75 0.226、max 0.421 |
| **必然饱和的帧** | `\|dx\| ≥ 0.0688` → **63%** 的帧（full 档 78%、coarse 档 78%、width 档 26%） |
| 实测饱和占比 | 63%（另有 27% 在死区 = 0），**落在比例区的只有 10%** |
| 分箱核对 | `\|dx\| ∈ (0.069, 0.08]` 起实测饱和率 **100%**；`≤ 0.05` 恒 0 ⇒ 阈值就是 0.0688 |
| 极限环 | `sway` 符号每 **7.6 帧（1.0 s）** 翻一次；按权限 ~0.10 m/s 修正中位行程 0.099 m 要 **1.0 s** ⇒ 两条时间尺度同量级 |
| 执行器死区 | `\|DOF\| < 0.138` 推力为 0（cfg 自注）⇒ **只降增益会把"一直顶满"换成"一直没推力"** |

结论：这不是"增益偏大"这么简单，而是**比例区（1.9%）远窄于误差分布**，控制器退化成继电器
（bang-bang），极限环的振幅由权限和帧率决定，而不是由增益决定。对照 `heave`（`kp=1.0`）
实测 **0% 饱和** ⇒ 同一个误差尺度下，sway 的 kp 大了 8 倍。

## 修法：降增益 **+ 执行器死区补偿**

`PID` 新增可选 `bias`（默认 0 = 不补偿，行为不变）：出死区后先把输出**抬到执行器死区之上**，
再随 kp 线性升到 `out_max`。

```
comm.motion.pid_sway: kp 8.0→1.0, kd 0.05→0.02, 新增 bias 0.138
```

同一批 236 个误差样本离线复算：

| 方案 | 饱和 | 死区(0) | 比例区 | 输出中位 |
|---|---|---|---|---|
| 现（kp=8，无补偿） | **64%** | 27% | 10% | 0.550 |
| kp=1.5 + bias=0.138 | 17% | 27% | 56% | 0.283 |
| **kp=1.0 + bias=0.138（采用）** | **1%** | 27% | **72%** | **0.240** |
| kp=1.5，不加 bias | 5% | 27% | 68% | 0.150 ← 中位已接近执行器死区 |

**回放实跑**（同一趟日志、整套新参数）：下发 `sway` 的饱和 **0%**、比例区 **32%**、
非零输出 **0.185 ~ 0.518 且 100% ≥ 执行器死区 0.138**（日志期非零最小只有 0.409，全在天花板附近）。

⚠️ `comm.motion.pid_sway` 是 **ball 与 gate 共用**（"一处调、两个任务同时生效"是既定不变量，
`tests` 里有专门用例钉它）⇒ 撞球的横向居中回路一并改变。回退 = `kp` 改回 8.0 并删掉 `bias`。

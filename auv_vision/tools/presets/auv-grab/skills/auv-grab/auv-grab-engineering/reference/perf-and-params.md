# 性能基线、参数手册与标定顺序

> 所有耗时/命中数字的出处：`grab/README.md`（PC + 板端，RDK X5 / A55，1280×720，700 帧真图）。
> ⚠️ **这些都是离线逐帧喂图测的，不含相机 read 与显示开销**。实时链路要另测。

## 1. 性能基线（✅ 板端实测）

**成本模型**：A55 上每一次全图（1280×720）uint8 pass ≈ **2.6 ms**（内存带宽受限）。所以单帧耗时 ≈ pass 数 × 2.6 ms，**优化 = 减少 pass 数**。

| 口径 | 板端单帧 | 帧率 |
|---|---|---|
| numpy 参考实现（`fast_mask=False`）整帧 | 87 ms | 11.5 FPS |
| **快掩膜**（`fast_mask=True`）整帧 | 64 ms | 15.6 FPS |
| **流式 ROI 跟踪**（`grab.track.enable: true`）跟踪稳态 | **25.6 ms** | **39 FPS** |
| 流式整体（含全图搜索/回退帧） | 31.1 ms | 32 FPS |
| 对照：YOLO 只 resize 640 送 BPU | 21.4 ms | 47 FPS（但要占 BPU，且夹取场景命中率差） |

**按球半径分段**（流式 ROI，板端）：`r ≤ 70 → 14 ms / 71 FPS`；`r 120–200 → 25 ms / 40 FPS`；`r 200–300 → 31 ms / 32 FPS`。

**读法**：CV 的耗时**随目标变大而升**（ROI 变大、掩膜 pass 变贵），YOLO 恒定 —— 这是两者的本质差别。所以"小目标阶段快、大目标阶段慢"是预期行为，别当成退化。

## 2. 两个性能坑（✅ 踩过，别重犯）

### 坑 1：ARM 上别用 16 位 / 稀疏索引

先写的"uint16 整数等价式 + `np.nonzero` 稀疏 HSV 索引"在 A55 上 **97.6 ms，比不优化还慢**（`cv2.multiply(dtype=CV_16U)`、`np.nonzero`、花式索引在 ARM 上都是标量实现）。

**正解**：全 uint8 + `cv2.LUT`（相对红占优判据的 LUT 与除法判据**逐格等价**，有单测保证）+ `cv2.inRange`。
`fast_mask=True`（默认）与 `fast_mask=False`（numpy 参考实现）**逐帧结果完全一致**，只差速度（15 ms vs 68.6 ms）—— 所以 `fast_mask=False` 是可信的对照基线，改掩膜逻辑时用它互证。

### 坑 2：ROI 尺寸公式与纵横比

- ROI 曾写成 `side = 4r + 80`（把 gain 乘在半径上又乘 2）⇒ 球半径 188 时 ROI = 832² = 69% 全图，实测"**ROI 模式反而比全图慢**"。现在 `side = 2(r + margin)`，`margin` 默认 64。
- **尺度归一化（`proc_side > 0`）必须按同一比例缩两轴**：ROI 贴画面边缘时会被截成非正方形（例 427×360），硬拉成正方形等于改纵横比，圆心回算就飘（单测抓到过 `cy` 差 52 px）。代码是 `cv2.resize(sub, None, fx=sc, fy=sc)`。
- 归一化代价实测：中心偏差 p50 0.71 px / p95 1.94 px、半径比 0.998（占球半径 0.38%）—— 夹取够用。

## 3. 参数手册（含义 + 调它的后果）

### `grab.cv.*`（`cv_ball.Params`）

| 参数 | 默认 | 含义 | 调大 / 调小的后果 |
|---|---|---|---|
| `dom_min` | 30 | `R - max(G,B)` 下限（绝对红占优） | 调大 → 暗球/远球漏检；调小 → 池底红光、瓦缝混入 |
| `rel_min` | 0.30 | 相对红占优下限（救衰减的暗球） | 调小 → 橙色物体混入；调大 → 暗球掉出 |
| `use_rel` / `use_hue` | True / True | 开关相对判据 / 色相门限 | 关掉相对判据 → 远距段命中率掉；关色相 → 橙色导轨混入 |
| `s_min` / `v_min` | 40 / 60 | HSV 门限 | **对水质最敏感**；换水/换灯必须重标 |
| `close_k` / `open_k` | 9 / 5 | 闭（并碎块/填孔）/ 开（去椒盐）核 | 调大 → 小目标被抹掉；调小 → 掩膜碎、圆度判据失效 |
| `fill_hole_frac` | 0.65 | 只填小于父轮廓该比例的孔 | 调大 → 背景大孔被误填（圆心被拉走）；调小 → 高光环形不闭合。**空心目标此参数失效，见 algorithm.md §2** |
| `min_area` | 30 | 掩膜面积下限（px²） | 调大 → 远距小球丢；调小 → 噪声斑点进拟合 |
| `circ_min` | 0.30 | 圆度 `4πA/P²` 下限 | 调大 → 被遮挡的月牙丢；调小 → 细长块进拟合 |
| `hull_fill_min` | 0.55 | `A / hull_area` 下限（凸性） | 同上 |
| `cov_min` | 0.35 | 拟合圆被掩膜覆盖比例下限 | 全盘≈0.95 / 被挡月牙≈0.5；调高 → 遮挡球丢。**空心目标必须重定义** |
| `min_arc_deg` | 150.0 | 拟合边界最小张角 | **防"细长条拟出大圆"的关键闸**；调低 → 假圆进 |
| `r_min` / `r_max` | 25.0 / 900.0 | 半径范围（px） | `r_min=25` 的由来：<30 px 的检出实测是**池底图案红点**。夹取场景若目标更小/更大要重标 |
| `fit_iters` / `fit_sigma` | 6 / 1.8 | 鲁棒拟合迭代次数 / 剔离群点倍数 | 迭代少 → 遮挡下拟合偏；sigma 小 → 把真实弧点也剔掉 |
| `merge_iou` | 0.6 | 圆 IoU 去重阈值 | **同心目标（环）不能用 IoU 去重**，见 algorithm.md §2 |
| `refine` / `hough_param2` / `hough_r_tol` | False / 28.0 / 1.45 | 可选 HoughCircles 精修 | 开 → 圆心更准但每帧多一次 Hough（耗时上升）；默认关 |
| `fast_mask` | True | uint8 SIMD 快路径 | **板端必须 True**；False 只用于互证 |

### `grab.track.*`（`BallTracker`）

| 参数 | 默认 | 含义 | 后果 |
|---|---|---|---|
| `enable` | true | ROI 跟踪开关 | False = 每帧全图（15 FPS，无状态，便于对照/调试） |
| `margin` | 64 | ROI 在目标外每边多留的像素 | 由实测最大帧间位移 ≈40 px 定（≈1.6×）；调小 → 目标出 ROI 频繁回退全图；调大 → ROI 变大、每帧变慢 |
| `proc_side` | 256 | ROI 归一化边长（0 = 关） | 关 → 大球时每帧变慢；开 → 有 0.71/1.94 px 的中心偏差（夹取可接受） |
| `max_lost` | 3 | 连续丢帧后回全图 | 调小 → 抖动时频繁全图（掉帧率）；调大 → 目标真丢了还在原地 ROI 里空转 |
| `edge_margin` | 6.0 | 贴 ROI 边界的检出判为不可信 | 目前**只能代码传参**（cfg 无键）；贴边=圆被切，圆心半径都不可信 |
| `min_roi` | 128 | ROI 最小边长 | 目标很小时别把 ROI 裁太小（掩膜形态学核相对过大） |

## 4. 标定顺序（换水质 / 换相机 / 换目标都要走一遍）

```
① 先固定 fast_mask=True、track.enable=False（全图、无状态）—— 排除跟踪带来的混淆
② 用 debug_maps + 真图看掩膜：先把 dom_min / use_rel / rel_min 调到"目标全进、背景基本不进"
③ 再调 s_min / v_min（HSV 门限，对水质最敏感）—— 到这一步掩膜应该已经干净
④ 再调形态学 close_k / open_k —— 看碎块与高光孔是否处理干净
⑤ 再调几何闸 min_area / circ_min / hull_fill_min / min_arc_deg —— 只在残余噪声上收紧
⑥ 最后调 cov_min（它是"拟合对不对"的判据，太早调会掩盖掩膜问题）
⑦ 打开 track.enable=True，用 fallback_rate 看 ROI 尺寸是否合理（margin 够不够）
⑧ 每次改一组、其余不动；每次都在**同一批帧**上对比命中率/耗时，不要凭单帧观感下结论
```

**换目标（例如小环）时不要沿用上表的数值**：从 ① 重来，并把"覆盖率/圆度/填空"这几个建立在实心圆上的判据按 `algorithm.md` §6 重定义。

## 5. 性能回归怎么量（写决策层时也要用同一套）

- **命中率**：整帧检出率（有真值标注时另算 precision/recall）；**按目标大小分桶**看，不要只看总数（远距段才是夹取的难点段）。
- **耗时**：`time.perf_counter()` 包住 `detect()` / `step()`，取 p50/p95，**分桶看**（半径小/中/大）。
- **回退率**：`BallTracker.stats()['fallback_rate']` —— 长期偏高说明 `margin`/`max_lost`/`proc_side` 没配好，或者目标真的很难跟。
- **长跑**：逐帧喂图几百帧的任务用 `nohup python3 -c '...' > /tmp/bench.log 2>&1 &` 起，再 `tail`/`grep` 轮询，不要在前台干等（常驻 shell 单条 300 s 上限，超时会重置 shell）。

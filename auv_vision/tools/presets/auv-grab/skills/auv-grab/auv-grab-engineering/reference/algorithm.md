# 算法：圆目标检测、夹取判据与相位机

> 分级标记：**✅ 本项目已实测** / **📐 工程判断（未在本项目验证）** / **❓ 待标定或待确认**。
> 引用的实测数字全部来自 `grab/README.md`（板端 700 帧），出处与口径见 `perf-and-params.md`。

## 1. 为什么夹取这条线不走 BPU（✅ 实测结论）

板端拿**撞球那版**检测权重（`yolo11n_detect_bayese_640x640_nv12.bin`）跑夹取场景 700 帧，按球大小分桶：

| 球半径 | 帧数 | YOLO 命中 | YOLO conf 中位 | 纯 CV 命中 |
|---|---|---|---|---|
| 25–40 px | 46 | **33%** | 0.00 | — |
| 40–70 px | 120 | **42%** | 0.10 | — |
| 70–120 px | 6 | 100% | 0.88 | — |
| 120–200 px | 161 | **99%** | 0.84 | — |
| 200–300 px | 209 | 90% | 0.49 | — |
| 整帧合计 | 700 | — | — | **549/700 = 78.4%** |

**读法（很重要，别过度解读）**：远距段（夹取任务一开始就在的那段）那版权重只有 33–42%，因为它**本来就不是给夹取训的**。这个对比说明的是"能不能顺手复用"，**不是"YOLO 不行"**。真要为夹取训一版权重是另一件事（要补远距样本 + 标注 + 量化 + 板端实测）。

结论：夹取用纯 CV，**把 BPU 让给门 keypoint**（过门才是真需要神经网络的）。

## 2. 圆目标检测的六步骨架（✅ 红球已实测，小环可借鉴但先验不同）

`handling/percept/cv_ball.py::detect` 的流程，每一步的"为什么"比参数值更重要：

| 步骤 | 做什么 | 为什么这么做 | 换目标时要重新想的 |
|---|---|---|---|
| 1 掩膜 | `R-max(G,B) ≥ dom_min` **或** `(R-max(G,B))/(R+max(G,B)+1) ≥ rel_min`，再叠 HSV 门限 | 水下红光衰减 ⇒ 暗球绝对差掉到阈值以下、比值却仍高，两条判据取**并**；色相门限挡橙色导轨（H≈20–30） | 环若不是红色，第 1 步整条作废，得换成形状/亮度/纹理先验 |
| 2 填高光孔 | 只填"面积 < `fill_hole_frac`(0.65) × 父轮廓"的孔 | 镜面高光把红球打成**红环**，不填则圆度/质心全错；真背景孔比球大，不会被误填 | 环**本身就是环** —— "填空"这个动作直接失效，必须改成"找环带/找内外边界" |
| 3 几何过滤 | 面积 / 圆度 `circ` / 凸性 `hull_fill` 下限 | 滤掉瓦缝红光、池底斑点这类细长或碎块 | 环带轮廓的圆度与凸性分布完全不同，阈值必须重新扫 |
| 4 鲁棒圆拟合 | Kasa 拟合 + 迭代剔离群点，要求边界**张角 ≥ `min_arc_deg`(150°)** | 球常被黑瓦条挡成月牙：月牙的弧仍是真圆的一段，拟合成立；"细长条"能拟出任意巨大的圆，用张角拦住 | 环被夹爪/水花挡掉一块时同理；但环的**内圈**会给出第二个圆，要防"拟到内圈" |
| 5 覆盖校验 | 拟合圆内掩膜占比 ≥ `cov_min`(0.35) | 全盘 ≈0.95、被挡月牙 ≈0.5；乱拟合会很低 | 环的覆盖率天然低（空心！），这条判据**必须重定义**（例如环带面积比环外接圆面积 ≈ 2t/r） |
| 6 去重 | 圆 IoU > `merge_iou`(0.6) 只留高分 | 同一球被切成几块时会出多个圆 | 环的内外圈是两个同心圆，IoU 去重会把它们**当成重复** —— 要去重必须按同心/半径差判断，不能只看 IoU |

**一句话**：红球这条链的每一步都嵌着"目标是**实心、偏红、不透光**的圆"这个先验。小环换掉任一先验，对应步骤就得重写，不是调参。

## 3. 关于"目标被夹爪带走"（✅ 实测到的现象）

`ball_tracker.py` 的注释记录：本数据集实测**球被夹爪带走时 ≈40 px/帧**（球半径范围 25–270 px）。这就是 `grab.track.margin` 默认 64 的由来（≈1.6× 最大帧间位移）。

对夹取阶段的含义：**夹住之后目标会突然加速**，跟踪器要么跟上、要么把这一帧判成跟丢。所以：
- 夹取动作一旦触发，控制逻辑**不应该**继续依赖"目标还在原位"的判据；
- 需要 `max_lost` 容忍 + 明确的"夹取后不再修正"的阶段出口，否则会在夹爪已经咬住时继续推。

## 4. 夹取的对准与接近判据怎么选（📐 工程判断，❓ 阈值待标定）

撞球用的是 **bbox 面积占比**（`Det.ratio`）+ 水平/竖直居中。夹取要换掉的点：

| 量 | 撞球怎么用 | 夹取该怎么用 | 理由 |
|---|---|---|---|
| 面积占比 | 判"够近了" | 用 `circle_to_ratio()`（按圆算），**不要**用 bbox 占比 | bbox 占比把圆形目标高估 4/π ≈ 1.27 倍；阈值换了量纲就会系统性提前/滞后 |
| 居中判据 | 水平 + 竖直居中即可 | 还要看**夹爪能否咬住**：目标在画面里的位置 ≠ 夹爪能夹到的位置 | 相机与夹爪有安装偏置（🔧 ❓ **待现场量**） |
| 判据来源 | 相位机里固定的像素阈值 | 先由"目标半径 → 实际距离"的关系反推（**需要标定**：已知球直径时，`像素半径 ∝ 1/距离`） | 阈值只有绑在几何上才可迁移；纯像素阈值换相机高度就废 |
| 时间维度 | EMA 平滑 + 丢失惯性 | 同样需要，但**惯性时长要短于夹取动作的耗时** | 夹取比撞球更晚才收敛，长惯性会让它错过窗口 |

要用到距离就先把标定做出来：本项目已有 `tools/analyze/calib/`（`pnp_calib.py` / `ruler_calib.py`）与门任务的前视相机模型（`gate/percept/geometry.py`）可参考；**红球/小环的"像素半径 ↔ 距离"关系本项目还没标定过**（❓）。

## 5. 相位机的候选形态（📐 未定，先纸面选型再写代码）

夹取两个阶段，每个阶段至少要有这几个状态（命名参考撞球与过门的既有习惯）：

```
SEARCH         找不到目标：平移扫视 / 缓慢前进探测（过门已确认 SEARCH 是平移不是旋转）
   ↓ 有目标
CENTER         把目标移到夹取判据要求的画面位置（水平/竖直）
   ↓ 连续 N 帧达标（N 要防抖，别用单帧）
APPROACH       分级前进（远快近慢）；接近过程中只做修正，不做大动作
   ↓ 半径/占比达标 + 居中达标
GRAB           停住（或极慢速）→ 等一帧静止 → 下发夹爪闭合 → 等待夹爪动作时间
   ↓
VERIFY/EXIT    确认（有回传就测，没有就等固定时间）→ 两阶段之间切换 / 结束 / 重试
```

要显式回答的问题（答不出就别写代码）：

1. **抖动 vs 速度**：CENTER 的容差窗口（±N px）与连续帧数，取大取小各自的代价（取小 → 在夹取瞬间抖动；取大 → 耗时，可能超时限）。
2. **丢目标怎么办**：多长时间内保持/惯性？超过之后回 CENTER 还是回 SEARCH？丢在 APPROACH 中途与丢在 CENTER 要不要区别对待？
3. **夹空一次怎么办**：重试几次？重试时要不要后退拉开距离？（❓ 取决于夹爪机制，见 `task-and-rules.md` §2.2）
4. **两阶段怎么交接**：阶段一成功后是"停在原地转阶段"还是"退回某个位姿再开始搜索小环"？（❓ 依赖赛事规则与场地布局）
5. **总时限**：按阶段切预算（如球 X s、环 Y s），到点必须有确定的收尾动作，不能悬在半路。
6. **失败边界**：什么条件下**主动放弃**（比"一直找"更安全），放弃后做什么。

**安全兜底（三项都要有）**：任何状态下丢目标/超时 → 全 0 停；接近段的最后一段要限速；**限深保护不得绕过**（`comm.depth_guard.min_depth_m = 0.55` 现场定死）。

## 6. 小环检测：❓ 还没有答案，但有"怎么找答案"的顺序

**不要**先写检测器再试。顺序是：

```
① 要素材       板端在小环场景下录一段（最好带已知尺寸参照物），存到工作区
② 量           实测：颜色分布（HSV 直方图）、环的外径/内径/厚度、像素尺度范围、
               是否有高光/透光、正对还是侧躺、被遮挡的典型形态
③ 选先验       按量到的结果挑一条路：
                  · 颜色可分（和红球一样强）→ 颜色掩膜 + 环带/同心圆约束
                  · 颜色不可分但有明显边界 → 边缘/梯度 + HoughCircles（注意：环会出内外双圆）
                  · 侧躺成椭圆 → 椭圆拟合 / 透视位姿，别硬套圆拟合
                  · 有独特纹理或标记 → 模板/特征匹配（但水下光照会毁掉模板，慎用）
④ 定判据       覆盖率/圆度这类量必须按"环带"重定义（见 §2 步骤 5/6 的两条警告）
⑤ 离线验证     与红球同一套流程：pytest + 逐帧喂图 + 命中率/耗时表
⑥ 才进决策层
```

📐 已知会踩的两个设计坑（因为红球的先验会"顺手"被继承）：
- **填空高光**（步骤 2）对空心环是**反作用**：把环当"被高光打成的红环之球"，会试图填掉环心，直接产出错误圆心。
- **IoU 去重**（步骤 6）会把环的**内圈与外圈**当成同一个目标的两个候选，只留一个 → 半径错一半。

❓ 如果现场发现小环是"红色小环"，也不代表能复用 `cv_ball.Params`：红球的 `cov_min`/`min_arc_deg`/`fill_hole_frac` 全部建立在实心圆上（见 §2）。正确做法是**单独一个 `grab.cv_ring` 参数段 + 单独的 detector**，共用 `Detection` 数据结构与 `BallTracker` 的跟踪骨架（跟踪只依赖"圆心+半径+位移"，与目标语义无关）。

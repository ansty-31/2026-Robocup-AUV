# board_forks.txt — 「本地≠板端是**故意的**」分叉清单（两个脚本共用的**唯一来源**）
#
# 谁在读它：
#   · deploy_to_board.sh     → 命中这里的路径**不上传**（打印 [skip]），板端保留自己的值
#   · check_board_parity.sh  → 命中这里的路径**不算不一致**（打印 [分叉]），
#                              否则 --board 会永远报 [板端不同] 并 exit 1，检查长期红着 = 白写
#   ⚠️ 别只往 deploy 脚本里加：那边加了这边没加，凭据检查就永远不绿（2026-09-27 踩过）。
#
# 格式：一行一个**工程根相对路径**，行内 `#` 之后是注释，空行忽略。
#
# 两种条目（检查器对两者一视同仁：都按"故意的差异"跳过，不做 md5 比对）：
#   ① 普通条目 = **整份跳过**：本地对该文件的任何改动都不上板端，板端/现场自己维护。
#      能用运行期环境变量解决的别用这条；必须分叉时，本地改了要在板端手工同步。
#   ② 带 `[sync+patch]` 标记 = **照常上传 + 上传后打补丁**（2026-10-06 起）：
#      本地是源、文件照常同步到板端，随后由 deploy 的「步骤 3b」把板端那份改成它该有的值。
#      为什么需要它：整份跳过会让板端拿不到文件里的**其它**更新 —— 2026-10-06 真踩到：
#      板端 settings.py 缺 STATE_GRAB/STATE_PLACE，新 handling 代码直接跑不起来。
#      目前实现的补丁只有一条：`base/cfg/settings.py` → 板端 `SIM_MODE = False`（真发串口）。
#      再加 `[sync+patch]` 条目时，**必须同时在 deploy 的步骤 3b 里为它加一个 case 分支**。
#
